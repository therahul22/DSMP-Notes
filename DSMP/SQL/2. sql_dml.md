## 1. Core Command Categories
* DDL (Data Definition): Alters the database structure (CREATE, ALTER, DROP, TRUNCATE).
* DML (Data Manipulation): Alters the actual data/rows (INSERT, SELECT, UPDATE, DELETE).
* DCL (Data Control): Manages permissions (GRANT, REVOKE).
* TCL (Transaction Control): Manages transactions (COMMIT, ROLLBACK).

---

## 2. DML Commands (The CRUD Operations)
DML handles the actual data inside your tables.
⚠️ *Interview Warning: Always use a WHERE clause with UPDATE and DELETE, or you will modify the entire table!*

C - Create (INSERT)
Adds new rows to a table.

    -- Insert specific columns
    INSERT INTO databasename.tablename (userid, name, age) VALUES (1, 'Alice', 22);

    -- Insert multiple rows at once
    INSERT INTO Users (userid, name) VALUES (2, 'Bob'), (3, 'Charlie');

R - Read (SELECT)
Retrieves data from a table.

    -- Select all columns
    SELECT * FROM phones;

    -- Filter specific columns
    SELECT brand, model, price FROM phones;

    -- Alias: Renaming columns in the output
    SELECT brand AS 'Manufacturer', price AS 'MRP' FROM phones;

    -- Creating Expressions using columns (e.g., applying a 10% discount)
    SELECT model, (price * 0.9) AS 'Discounted_Price' FROM phones;

    -- Constants: Adding a hardcoded column to the output
    SELECT 'Smartphone' AS Category, brand, model FROM phones;

DISTINCT (Removing Duplicates):
    -- Unique values from a single column
    SELECT DISTINCT brand FROM phones;

    -- Distinct Combinations (Unique pairs of brand and processor)
    SELECT DISTINCT brand, processor FROM phones;

U - Update (UPDATE)
Modifies existing data in a table.

    -- Update a single column
    UPDATE Users SET age = 23 WHERE userid = 1;

    -- Update multiple columns
    UPDATE Users SET age = 25, name = 'Robert' WHERE userid = 2;

D - Delete (DELETE)
Removes rows from a table.

    -- Delete specific rows
    DELETE FROM Users WHERE userid = 3;

    -- Delete ALL rows (but keeps table structure)
    DELETE FROM Users;

## 3. DDL Commands (Schema & Structure)

Databases:

    CREATE DATABASE company_db;
    DROP DATABASE company_db;

Tables (Create & Drop):

    CREATE TABLE Users (
        userid INT PRIMARY KEY,
        name VARCHAR(50) NOT NULL,
        age INT DEFAULT 18
    );

    DROP TABLE Users;      -- Destroys table and data completely.
    TRUNCATE TABLE Users;  -- Deletes all data, resets Auto-Increment, keeps structure.

Tables (Alter):

    ALTER TABLE Users ADD email VARCHAR(100);          -- Add column
    ALTER TABLE Users DROP COLUMN email;               -- Drop column
    ALTER TABLE Users MODIFY COLUMN name VARCHAR(255); -- Change data type

## 4. Constraints & Data Integrity

### Rules applied to columns to prevent invalid data.
* NOT NULL: Cannot be empty.
* UNIQUE: All values must be different.
* PRIMARY KEY: NOT NULL + UNIQUE. Identifies the row.
* FOREIGN KEY: Links to a Primary Key in another table.
* CHECK: Ensures a condition is met (e.g., age >= 18).
* DEFAULT: Sets a fallback value.

### Foreign Key Referential Actions:
* CASCADE: If parent is deleted/updated, automatically delete/update child rows.
* RESTRICT: Prevents deletion of parent if child exists.
* SET NULL: If parent is deleted, child foreign key becomes NULL.

## 5. SQL Operators (Filtering Data)

### Logical Operators:

* AND / OR: Combine multiple conditions.
* IN / NOT IN: Match against a list of values.
* BETWEEN: Filter within a range (inclusive).
* IS NULL: Check for missing values (Never use `= NULL`).
* EXISTS: Returns TRUE if a subquery returns at least one row.

    -- Examples
    SELECT * FROM Users WHERE age BETWEEN 20 AND 30;

    SELECT * FROM Users WHERE name IN ('Alice', 'Bob');

### String Operators (Pattern Matching):

* LIKE: Search using wildcards (`%` = any sequence, `_` = single character).
    
    -- Find names starting with 'A'
    SELECT * FROM Users WHERE name LIKE 'A%';
    
    -- Find names having 'o' as the second letter
    SELECT * FROM Users WHERE name LIKE '_o%';

Comparison Operators:
* `=`, `!=` (or `<>`), `>`, `<`, `>=`, `<=`

Aggregate Functions (Math on columns):
* COUNT(), SUM(), AVG(), MIN(), MAX()

## 6. Interview Classic: DROP vs. TRUNCATE vs. DELETE

* DROP (DDL): Destroys table structure, data, and indexes. Cannot be rolled back.
* TRUNCATE (DDL): Wipes all rows quickly. Resets AUTO_INCREMENT. Cannot be rolled back.
* DELETE (DML): Deletes rows one-by-one. Does NOT reset AUTO_INCREMENT. Can be rolled back.

## 7. Order of Execution

When you write a SQL query, the database engine does NOT process it top-to-bottom.

1. FROM          (Chooses and joins tables)
2. JOIN          (Links data)
3. WHERE         (Filters base data/rows)
4. GROUP BY      (Aggregates data into groups)
5. HAVING        (Filters the grouped data)
6. SELECT        (Returns the final columns/expressions)
7. DISTINCT      (Removes duplicates from the result)
8. ORDER BY      (Sorts the final output)

## 8. Aggregate Functions

MAX / MIN:
    
    SELECT MIN(price), MAX(price) FROM phones;
    
    SELECT MAX(price) FROM phones WHERE brand = 'Samsung';

AVG & SUM:
    
    SELECT AVG(rating) FROM phones WHERE brand = 'Apple';

COUNT vs COUNT(DISTINCT):

    -- Find the total number of OnePlus phones (Counts rows)
    SELECT COUNT(*) FROM phones WHERE brand = 'OnePlus';

    -- Find the total number of unique brands available (Counts distinct values)
    SELECT COUNT(DISTINCT brand) FROM phones;

Statistical Aggregates:

    SELECT STD(screen_size) FROM phones;

    SELECT VAR(price) FROM phones WHERE brand = 'Xiaomi';


## 9. Scalar Functions

ABS (Absolute Value):

    SELECT model, ABS(rating - (SELECT AVG(rating) FROM phones)) AS 'Rating_Diff' 
    FROM phones WHERE brand = 'Samsung';

ROUND, CEIL, FLOOR:

    SELECT ROUND(ppi, 1) FROM phones;

    SELECT CEIL(price), FLOOR(price) FROM phones;
