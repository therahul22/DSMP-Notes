# SQL Subqueries Revision Guide

## 1. What is a Subquery?
A subquery is a query nested inside another query (e.g., inside a SELECT, INSERT, UPDATE, or DELETE statement). The database engine generally evaluates the inner query first, and then passes its result to the outer query.

    -- Example: Find the movie with the highest rating
    SELECT * FROM movies 
    WHERE score = (SELECT MAX(score) FROM movies);


## 2. Types of Independent Subqueries
Independent subqueries can be run on their own. They don't depend on the outer query for execution. They are classified by the "shape" of the data they return.

### Scalar Subquery (Returns 1 Row, 1 Column):
Acts as a single value. Often used with `=`, `<`, `>` operators.

    -- Find movies with a rating higher than the overall average
    SELECT name FROM movies 
    WHERE score > (SELECT AVG(score) FROM movies);

### Row Subquery (Returns Multiple Rows, 1 Column):
Acts as a list. Must be used with operators like `IN`, `NOT IN`, `ANY`, or `ALL`.

    -- Find all users who have never placed an order
    SELECT * FROM users 
    WHERE user_id NOT IN (SELECT DISTINCT user_id FROM orders);

### Table Subquery (Returns Multiple Rows, Multiple Columns):
Acts as a temporary table. Usually found in the `FROM` clause. (Note: Always give table subqueries an alias).

    -- Find the highest rated movie of each genre
    SELECT genre, MAX(score) 
    FROM (SELECT genre, score FROM movies WHERE votes > 25000) AS filtered_movies
    GROUP BY genre;


## 3. Correlated Subqueries

A correlated subquery depends on the outer query to run. It executes once for EVERY row processed by the outer query. This makes them powerful but computationally expensive (slow).

    -- Example: Find all movies with a rating higher than the average rating of their specific genre.
    -- Notice how the inner query references 'm1.genre' from the outer query.
    SELECT name, genre, score 
    FROM movies m1
    WHERE score > (
        SELECT AVG(score) 
        FROM movies m2 
        WHERE m1.genre = m2.genre
    );


## 4. Subqueries in Different Clauses

### In the SELECT Clause: 
Used to calculate values on the fly for each row. Can be inefficient if correlated.
 
    -- Get the percentage of votes for each movie compared to total votes
    SELECT name, votes, 
           (votes / (SELECT SUM(votes) FROM movies)) * 100 AS vote_percentage
    FROM movies;

### In the FROM Clause: 
Used to create a temporary table that you immediately query against.

    -- Display the average rating of restaurants (first find avg per restaurant, then avg overall)
    SELECT AVG(avg_rating) 
    FROM (
        SELECT restaurant_id, AVG(rating) as avg_rating 
        FROM reviews 
        GROUP BY restaurant_id
    ) AS restaurant_averages;

### In the HAVING Clause: 
Used to filter grouped data based on an aggregate calculation.

    -- Find genres where the average genre score is greater than the overall average score
    SELECT genre, AVG(score) 
    FROM movies 
    GROUP BY genre 
    HAVING AVG(score) > (SELECT AVG(score) FROM movies);


## 5. Subqueries with INSERT, UPDATE, DELETE

### INSERT:

    -- Populate a 'loyal_customers' table with users who ordered more than 3 times
    INSERT INTO loyal_customers (user_id, name)
    SELECT user_id, name FROM users 
    WHERE user_id IN (
        SELECT user_id FROM orders GROUP BY user_id HAVING COUNT(*) > 3
    );

### UPDATE:

    -- Give a 10% bonus to a customer's wallet based on their total order value
    UPDATE loyal_customers lc
    SET wallet_balance = wallet_balance + (
        SELECT SUM(amount) * 0.1 FROM orders o WHERE o.user_id = lc.user_id
    );

### DELETE:

    -- Delete all customers who have never ordered
    DELETE FROM users 
    WHERE user_id NOT IN (SELECT DISTINCT user_id FROM orders);
