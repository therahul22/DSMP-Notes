# SQL Sorting, Limiting & Grouping

## 1. Sorting Data (ORDER BY)
The `ORDER BY` clause sorts the result set in Ascending (`ASC` - default) or Descending (`DESC`) order.

Basic Sorting:

    -- Sort phones by price from highest to lowest
    SELECT * FROM phones ORDER BY price DESC;

Sorting by Multiple Columns:

    -- Sorts first by brand (A-Z). If brands are identical, sorts those ties by price (High to Low).
    SELECT * FROM phones ORDER BY brand ASC, price DESC;

Creating and Sorting by a Derived Column:

    -- You can use an alias created in the SELECT clause directly in the ORDER BY clause
    SELECT model, (price * 0.9) AS discounted_price 
    FROM phones 
    ORDER BY discounted_price ASC;


## 2. Limiting Results (LIMIT)

`LIMIT` restricts the number of rows returned. It is frequently paired with `ORDER BY` to find top or bottom values.

Basic Limit:

    -- Find the top 5 most expensive phones
    SELECT * FROM phones ORDER BY price DESC LIMIT 5;

The "Nth Max/Min" Trick (LIMIT offset, count):

Syntax: `LIMIT x, y` means "Skip the first `x` rows, and then return the next `y` rows."
    
    -- Find the 2nd most expensive phone (Skip 1, Take 1)
    SELECT * FROM phones ORDER BY price DESC LIMIT 1, 1;

    -- Find the 3rd cheapest phone (Skip 2, Take 1)
    SELECT * FROM phones ORDER BY price ASC LIMIT 2, 1;

    -- Find the 4th, 5th, and 6th most expensive phones (Skip 3, Take 3)
    SELECT * FROM phones ORDER BY price DESC LIMIT 3, 3;


## 3. Grouping Data (GROUP BY)

`GROUP BY` groups rows that have the same values into summary rows. It is almost always used with aggregate functions like `COUNT()`, `MAX()`, `MIN()`, `SUM()`, or `AVG()`.

Grouping by a Single Column:

    -- Find the average price of phones for each brand
    SELECT brand, AVG(price) AS average_price 
    FROM phones 
    GROUP BY brand;

Grouping by Multiple Columns (Sub-grouping):

    -- Find the average price for each processor type, broken down within each brand
    SELECT brand, processor, AVG(price) AS average_price 
    FROM phones 
    GROUP BY brand, processor;


## 4. Filtering: WHERE vs. HAVING (Crucial Interview Topic)

Both clauses filter data, but they happen at different stages of execution. 

* WHERE: Filters raw rows BEFORE the data is grouped. (Cannot use aggregate functions here).
* HAVING: Filters the summarized groups AFTER the data is grouped. (Used exclusively with aggregate functions).

Combined Example:

    -- 1. Filter out cheap phones (WHERE)
    -- 2. Group the remaining phones by brand (GROUP BY)
    -- 3. Only keep brands whose resulting average price is above 50,000 (HAVING)
    
    SELECT brand, AVG(price) AS avg_price
    FROM phones
    WHERE price > 10000          -- Happens BEFORE grouping
    GROUP BY brand
    HAVING AVG(price) > 50000;   -- Happens AFTER grouping
