## 1. Core Paradigm: Window Functions vs. Aggregates

### Concept Definition
* **Aggregate Functions (GROUP BY)**: Collapse multiple rows into a structural summary row. Individual row identity is lost.
* **Window Functions (OVER())**: Perform calculations across a specified set of rows (a "window") related to the current row while **preserving individual row identities**.

### Base Syntax

```sql
FUNCTION() OVER (
    PARTITION BY partition_column
    ORDER BY sort_column
    ROWS/RANGE frame_clause
)
```
---

## 2. Core Clauses of the Window Specification

### PARTITION BY (Data Grouping)
Divides the full result set into localized logical buckets. The window calculation isolates its evaluation per bucket and resets its state when traversing a partition boundary. If omitted, the function treats the entire dataset as one single partition.

### ORDER BY (Sequence Definition)
Establishes the linear arrangement of row evaluations inside each partition. This is structurally critical for processing rank indices, running accumulations, or navigating local offsets.

### WINDOW Named Clause (Optimization)
When multiple window calculations share identical configurations, use the `WINDOW` keyword at the base of the block to define a reusable alias.

```sql
SELECT 
    SUM(batsman_run) OVER w AS 'career_runs',
    AVG(batsman_run) OVER w AS 'career_avg'
FROM ipl
GROUP BY ID
WINDOW w AS (ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW);

```

## 3. Categorized Function Reference & Query Implementations

### A. Ranking Functions
Tools designed to evaluate linear positions based on order rules.

* ROW_NUMBER(): Assigns a strict sequential integer sequence starting from 1 (e.g., 1, 2, 3, 4). Tied records receive arbitrary distinct rankings.
* RANK(): Assigns positional ranks based on ties. When matches exist, rows share identical rank values, and subsequent ranks are skipped (e.g., 1, 2, 2, 4).
* DENSE_RANK(): Assigns positional ranks based on ties. Rows share identical rank values, but subsequent sequence indices increment sequentially without gaps (e.g., 1, 2, 2, 3).

#### Example: Finding Top N Records Within Groups
Find the top 5 run-scoring batters for every unique batting team.

```sql
SELECT * FROM (
    SELECT BattingTeam, batter, SUM(batsman_run) AS 'total_runs',
    DENSE_RANK() OVER(PARTITION BY BattingTeam ORDER BY SUM(batsman_run) DESC) AS 'rank_within_team'
    FROM ipl
    GROUP BY BattingTeam, batter
) t
WHERE t.rank_within_team < 6
ORDER BY t.BattingTeam, t.rank_within_team;

```
---

### B. Value Navigation Functions
Used to inspect leading or lagging adjacent values relative to the cursor position without forcing self-joins.

* LAG(col, offset): Retrieves a value from a row located a specific index prior to the current row position.
* LEAD(col, offset): Retrieves a value from a row located a specific index subsequent to the current row position.

#### Example: Calculating Period-over-Period Percentage Growth Trend
Evaluate the quarterly percentage changes of channel traffic views over linear time.

```sql
SELECT YEAR(Date), QUARTER(Date), SUM(views) AS 'views',
((SUM(views) - LAG(SUM(views)) OVER(ORDER BY YEAR(Date), QUARTER(Date))) / 
  LAG(SUM(views)) OVER(ORDER BY YEAR(Date), QUARTER(Date))) * 100 AS 'Percent_change'
FROM youtube_views
GROUP BY YEAR(Date), QUARTER(Date)
ORDER BY YEAR(Date), QUARTER(Date);

```
#### Example: Fixed Index Offset Comparisons (Weekly Lookback)
Compare a specific day's metric against the matching day from the exact prior week.

```sql
SELECT *,
((Views - LAG(Views, 7) OVER(ORDER BY Date)) / 
  LAG(Views, 7) OVER(ORDER BY Date)) * 100 AS 'weekly_percent_change'
FROM youtube_views;

```

### C. Percentiles & Statistical Distribution

* NTILE(n): Divides an ordered partition's row distribution into n roughly equal, ranked buckets, assigning an integer label from 1 to n.
* CUME_DIST(): Calculates the relative cumulative distribution position of a value (returns a range from >0 to 1). Represents the percentage of rows evaluating less than or equal to the current row value.
* PERCENTILE_CONT(p): Continuous percentile interpolation assuming a continuous data distribution.
* PERCENTILE_DISC(p): Discrete percentile matching. Returns an exact value present in the source dataset corresponding to the target fraction.

#### Example: Multi-Tier Categorization via Buckets
Divide devices into separate commercial segments (budget, mid-range, premium) based on ordered cost metrics within brands.

```sql
SELECT brand_name, model, price, 
CASE 
    WHEN bucket = 1 THEN 'budget'
    WHEN bucket = 2 THEN 'mid-range'
    WHEN bucket = 3 THEN 'premium'
END AS 'phone_type'
FROM (
    SELECT brand_name, model, price,
    NTILE(3) OVER(PARTITION BY brand_name ORDER BY price) AS 'bucket' 
    FROM smartphones
) t;

```
#### Example: Filtering Top Percentile Extremes
Isolate data targets mapping exclusively inside the top 10% highest evaluation brackets.

```sql
SELECT * FROM (
    SELECT *,
    CUME_DIST() OVER(ORDER BY marks) AS 'Percentile_Score'
    FROM marks
) t
WHERE t.Percentile_Score > 0.90;

```
#### Example: Outlier Detection via Interquartile Range (IQR)
Filter for records below the lower boundary (Q1 - 1.5 * IQR) to catch lower statistical anomalies.

```sql
SELECT * FROM (
    SELECT *,
    PERCENTILE_CONT(0.25) WITHIN GROUP(ORDER BY marks) OVER() AS 'Q1',
    PERCENTILE_CONT(0.75) WITHIN GROUP(ORDER BY marks) OVER() AS 'Q3'
    FROM marks
) t
WHERE t.marks <= t.Q1 - (1.5 * (t.Q3 - t.Q1));

```

## 4. The FRAME Clause (The "Sliding Window")

### Structural Mechanics
The Frame sub-clause defines an explicit subset of rows inside a partition that a window function evaluates for the current row.

ROWS BETWEEN [start_boundary] AND [end_boundary]

### Standard Boundary Terminology
* UNBOUNDED PRECEDING: From the first structural row of the partition.
* CURRENT ROW: Stops at or references the active processing index.
* UNBOUNDED FOLLOWING: Extends to the final terminating row of the partition.
* n PRECEDING / n FOLLOWING: An exact sliding numeric row offset context.

#### Example: Building a Rolling Context Windows
Isolate a 10-match moving rolling calculation (the 9 matching records prior plus the current active record) to smooth metrics over time.

```
SELECT * FROM (
    SELECT 
        CONCAT("Match-", CAST(ROW_NUMBER() OVER(ORDER BY ID) AS CHAR)) AS 'match_no',
        SUM(batsman_run) AS 'runs_scored',
        SUM(SUM(batsman_run)) OVER w AS 'career_runs',
        AVG(SUM(batsman_run)) OVER w AS 'career_avg',
        AVG(SUM(batsman_run)) OVER(ROWS BETWEEN 9 PRECEDING AND CURRENT ROW) AS 'rolling_avg'
    FROM ipl
    WHERE batter = 'V Kohli'
    GROUP BY ID
    WINDOW w AS (ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)
) t;

```

## 5. Critical Pitfalls & Query Execution Order

### The WHERE Clause Restriction
**Confusion Point:** Why does SELECT * FROM table WHERE ROW_NUMBER() OVER() = 1 fail?
**The Reason:** In the relational engine execution order, WHERE processing happens before select column evaluations and window processing calculations. At the time of filtering, window states do not exist.
**The Universal Fix:** Wrap your query block inside an explicit subquery or a Common Table Expression (CTE) to evaluate and freeze window columns before applying external filter constraints.

### Calculating Proportional Shares (The "Total" Context)
To evaluate the relative contribution percentage of an individual item against the collective total, divide a local metric by a global window aggregate (OVER() with no parameters).

```
SELECT f_name,
(total_value / SUM(total_value) OVER()) * 100 AS 'percent_of_total'
FROM (
    SELECT f_id, SUM(amount) AS 'total_value' 
    FROM orders t1
    JOIN order_details t2 ON t1.order_id = t2.order_id
    WHERE r_id = 5
    GROUP BY f_id
) t
JOIN food t3 ON t.f_id = t3.f_id
ORDER BY percent_of_total DESC;
```

# Window Functions — Part 2 (Advanced Applications & Statistical Metrics)


## 6. Cumulative Calculations & Aggregates over Time
Unlike standard group summaries, window functions allow us to calculate progressive accumulations directly alongside individual transaction logs.

### A. Cumulative Sum (Running Total)
Concept Definition: Calculates the sum of a target metric up to the current row index, incorporating all preceding values in the calculation.

    SELECT 
        month, year, sales,
        SUM(sales) OVER(ORDER BY year, month) AS 'cumulative_sum'
    FROM sales_data;


### B. Cumulative Average
Concept Definition: Evaluates the continuous arithmetic mean of a metric from the start of a boundary up to the active processing row.

SQL Implementation (Partitioned by Group):

    SELECT 
        Student_ID, Test_Number, Score,
        AVG(Score) OVER(
            PARTITION BY Student_ID 
            ORDER BY Test_Number
        ) AS 'Cumulative_Avg'
    FROM student_scores;

## 7. Moving Frameworks: Running/Moving Averages

Concept Definition: A statistical technique designed to smooth volatile fluctuations or high-frequency noise by evaluating metrics across a dynamic, sliding index window of consecutive data points.
Mechanics: As the evaluation cursor moves forward sequentially, the execution framework drops the oldest data point outside the sliding frame constraint and incorporates the newest incoming point.

SQL Implementation (Fixed Multi-Match Lookback Frame):

    -- Evaluates the rolling current form based on a 5-match lookback window
    SELECT 
        match_id, runs_scored,
        AVG(runs_scored) OVER(
            ORDER BY match_id 
            ROWS BETWEEN 4 PRECEDING AND CURRENT ROW
        ) AS 'running_avg_5_matches'
    FROM batsman_stats;


## 8. Relative Share Analysis: Proportional Distribution

### A. Percent of Total
Concept Definition: Determines the proportional weight or contribution scale of a localized discrete value against the universal sum of the population.


SQL Implementation (Global Context vs. Local Item):

    SELECT 
        category, total_sales,
        (total_sales / SUM(total_sales) OVER()) * 100 AS 'percent_of_total'
    FROM category_sales;


## 9. Statistical Percentiles, Quantiles & Distribution

### A. Quantiles & Quantization Mechanics
Concept Definition: Data grouping boundaries that slice an ordered dataset distribution into an arbitrary number of equally sized intervals, such as Quartiles (4 parts), Deciles (10 parts), or Percentiles (100 parts). Each boundary represents a threshold below which a specific percentage of data falls. 

### B. Continuous vs. Discrete Percentiles
PERCENTILE_CONT(p): Calculates an interpolated mathematical percentile value by assuming a uniform continuous dataset distribution. The resulting figure is an approximation and may not exist as an exact record inside the source table.
PERCENTILE_DISC(p): Computes a discrete percentile by identifying the actual nearest data record that matches or exceeds the fraction. The resulting figure is always present within the source dataset.

### C. Cumulative Distribution Functions (CUME_DIST)
Concept Definition: Evaluates the relative probability position of a specific record value by calculating the percentage of rows that evaluate to a value less than or equal to the current row value.
Formula Mechanics: It is obtained by dividing the number of rows with a value less than or equal to the current row value by the total row count.


    SELECT 
        marks,
        CUME_DIST() OVER(ORDER BY marks) AS 'cume_dist_score'
    FROM exam_results;

## 10. Advanced Multi-Level Architecture: Composite Partitioning
Concept Definition: Window calculation frameworks are not limited to a single categorization column. You can declare composite grouping strategies inside the PARTITION BY clause to isolate evaluations across multiple intersecting dimensions concurrently.


    SELECT 
        branch_id, academic_year, student_name, marks,
        AVG(marks) OVER(PARTITION BY branch_id, academic_year) AS 'branch_yearly_avg'
    FROM college_records;
