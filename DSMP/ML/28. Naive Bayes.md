# 🚀 Naive Bayes: The Ultimate Interview Cheat Sheet

## 1. Core Concept & The "Naive" Hack
Naive Bayes is a **generative, probabilistic classifier** primarily used for text classification (Spam filtering, Sentiment Analysis).

### The Math (Bayes' Theorem)
Given a query point with features $X = \langle x_1, x_2, \dots, x_n \rangle$, we want to find the class $y_k$ that maximizes the posterior probability:

$$P(y_k \mid x_1, x_2, \dots, x_n) \propto P(y_k) \cdot P(x_1, x_2, \dots, x_n \mid y_k)$$

> 💡 **Interview Note:** We completely **drop the denominator $P(X)$** because it is a constant scaling factor across all classes during comparison optimization.

### Why is it "Naive"?
In reality, features exhibit natural dependencies. However, tracking the joint combination of hundreds of features leads to the **Data Sparsity Problem** (if a specific multi-feature combination isn't found in the training dataset, its probability collapses to $0$).

* **The Assumption:** We assume all features are **conditionally independent** given the class label. 
* **The Math Simplification:** This reduces a computationally heavy joint probability into a clean, simple product of individual conditional probabilities:

$$\hat{y} = \arg\max_{y_k} \left[ P(y_k) \prod_{i=1}^{n} P(x_i \mid y_k) \right]$$

## ⚙️ 2. Production Workflow (Under the Hood)
* **Training Phase (Pre-computation):** The model calculates all class priors $P(y_k)$ and feature likelihoods $P(x_i \mid y_k)$ in a single pass over the dataset ($O(N \cdot n)$ time complexity) and stores them in a structured **Lookup Dictionary**.
* **Testing Phase (O(1) Lookup):** For a new query point, the model bypasses raw data scanning. It performs light, constant-time lookups in its dictionary and simply **multiplies the matching probabilities together**, rendering inference blazingly fast.

## 📊 3. Handling Continuous Numerical Data (Gaussian NB)
When features are continuous (e.g., `Age = 55`), the probability count of that exact decimal value in the training set is often zero.

* **The Solution:** Assume the continuous feature follows a **Gaussian (Normal) Distribution**.
* **Training:** Calculate the **Mean ($\mu$)** and **Standard Deviation ($\sigma$)** for the continuous column, computed *separately* for each target class.
* **Testing:** Plug the incoming query value $x$ directly into the Gaussian Probability Density Function (PDF) to extract its likelihood height score on the normal bell curve:
  
  $$f(x) = \frac{1}{\sigma \sqrt{2\pi}} e^{-\frac{1}{2}\left(\frac{x - \mu}{\sigma}\right)^2}$$

### What if the data is NOT Gaussian? (Top 4 Workarounds)
1. **Data Transformations:** Apply mathematical operations like Logarithm ($\log(x)$), Square Root ($\sqrt{x}$), or Reciprocal transformations to contract heavily skewed distributions into a normal curve.
2. **Discretization (Binning):** Chop the continuous column into discrete intervals (Equal-Width bins, Equal-Frequency bins, or natural groupings via 1D K-Means clustering) and map them as categorical categories.
3. **Kernel Density Estimation (KDE):** Deploy a non-parametric method to organically trace a smooth, customized probability density function if the underlying distribution features irregular peaks.
4. **Alternative Distributions:** Swap out the Gaussian assumption for matching physical laws, such as **Poisson Distribution** (for discrete count metrics) or **Exponential Distribution** (for duration or timeframe metrics).

## 📝 4. Text Classification Pipeline (Bag of Words)

**Pipeline Flow:** Raw Review -> Text Preprocessing -> Vectorization (BoW) -> Naive Bayes Model

### Step 1: Text Preprocessing
1. **HTML & Clean-up:** Strip away web elements and text styling blocks using regular expressions and clean out irregular punctuation marks.
2. **Normalization:** Convert all string tokens to lowercase to ensure consistency.
3. **Stopwords Removal:** Drop high-frequency, low-semantic tokens (*the, an, is, a*) utilizing standard NLP lexicons (e.g., NLTK).
4. **Stemming:** Truncate words down to their baseline linguistic roots (e.g., *loved/loving* to *love*) using standard algorithms like PorterStemmer.

### Step 2: Vectorization (Bag of Words)
* Extract the **Top K most frequent words** across the entire text corpus (e.g., setting max_features=2500) to form the vocabulary feature dimensions.
* Transform each cleaned document into a static array vector of size 1 x K tracking discrete token frequency counts (e.g., [love: 2, hate: 0, movie: 1]).

## 🏆 5. Choosing the Right Variant (Crucial Interview Question)

When evaluating classifiers over sparse matrix representations (like Bag of Words or Term Frequencies), your specific choice of Naive Bayes variant heavily dictates performance:

| Naive Bayes Variant | Structural Logic | Performance on Sparse Text | Why? |
| :--- | :--- | :--- | :--- |
| **BernoulliNB** | Binarizes features completely ($1$ if the token exists, $0$ if absent). | **Best (~83.5%)** | For shorter text or sentiment analysis tasks, the explicit *presence* of key descriptive indicators dictates the signal far more effectively than structural count repeat frequencies. |
| **MultinomialNB** | Leverages raw, discrete integer counts ($0, 1, 2 \dots$). | **Strong (~82.9%)** | Excellent for longer, diverse documents where the absolute frequency volume of target keywords explicitly outlines topic alignment. |
| **GaussianNB** | Fits a continuous normal bell curve over values. | **Poor (~71.8%)** | Forcing a continuous normal curve function over sparse multi-dimensional arrays saturated with structural zeros distorts variance parameters and degrades performance. |
