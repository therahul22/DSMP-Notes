# K-Nearest Neighbors (KNN) Lecture Notes

## 1. Introduction & Intuition of KNN
* **Real-World Logic:** The core logic of the KNN algorithm is deeply inspired by real-world behavior. A famous quote by entrepreneur Jim Rohn perfectly captures its essence: *"You are the average of the five people you spend the most time with."*
* **Core Principle:** KNN operates on a very simple premise—**you are like your neighbors**. 

### The Problem Setup
* Imagine a dataset of $1,000$ students containing their **CGPA**, **IQ**, and whether they got **Placed (1) or Not Placed (0)**.
* The goal is to build a Machine Learning model that can predict whether a new student will get placed based on their CGPA and IQ.

---

## 2. Geometric Understanding: How KNN Works
When visualized in a 2D space (with CGPA on one axis and IQ on the other):
1. **Plot the Data:** Existing students are plotted using two colors (e.g., Blue for Placed, Pink for Not Placed).
2. **Choose the Value of $K$:** You must decide on a value for $K$ (e.g., $K = 3$), which means the algorithm will consider the 3 nearest neighbors.
3. **Calculate Distances:** When a new student (query point) arrives, the algorithm calculates its distance from **all** existing points in the dataset. Usually, **Euclidean distance** is used.
4. **Sort and Select:** All calculated distances are sorted in ascending order, and the top $K$ (closest) points are selected.
5. **Majority Count (Voting):** A democracy-style vote is conducted among the $K$ neighbors. Whichever class has the majority becomes the predicted label for the new point. 
   * *Example:* If among 3 neighbors, two say "Placed (1)" and one says "Not Placed (0)", the final prediction is "Placed (1)".

## 4. How to Choose the Best Value of $K$?
The performance of KNN changes significantly based on the value of $K$. There are two primary approaches to finding the optimal $K$:

### A. Heuristic Approach
* A common rule of thumb used by researchers is to set $K = \sqrt{n}$, where $n$ is the total number of observations (rows) in your data.
* **Tip:** It is often recommended to choose an **odd number** for $K$ to avoid tie breaks (conflicts) during the majority voting phase.

### B. Experimental Approach (Hyperparameter Tuning)
* Run a loop testing multiple values of $K$ (e.g., $K = 1$ to $15$).
* For each value, train a KNN model and calculate its accuracy score.
* Plot $K$ values on the X-axis and Accuracy on the Y-axis. Choose the $K$ value that yields the highest accuracy (in the video's example, $K = 3$ gave the best results).

## 5. Decision Surfaces & Boundaries
* **Decision Surface:** A visual tool (or boundary) used in classification tasks to divide the coordinate space into distinct regions corresponding to each class label.
* **How it helps:** Once plotted, you don't even need to run a prediction function—you can instantly tell which class a new point belongs to based on the region it falls into.
* **Library Note:** While it can be manually plotted, python libraries like `mlxtend` provide built-in functions to plot decision surfaces easily.

## 6. Overfitting and Underfitting in KNN
Changing the value of $K$ drastically alters the behavior of the decision boundary:

### Small $K$ Values (e.g., $K = 1$) $\rightarrow$ Overfitting
* The model looks only at its absolute closest neighbor.
* The decision boundary becomes highly complex, jagged, and memorizes minor noise/outliers in the data.
* This leads to **High Variance** (performing well on training data but poorly on unseen test data).

### Large $K$ Values (e.g., $K = \text{Total Dataset Size } n$) $\rightarrow$ Underfitting
* If $K = 200$ (for a dataset of 200 points), the model will always look at the entire dataset for every single query point.
* The majority vote will **always** be won by whichever class is dominant in the overall dataset.
* The decision boundary becomes overly generalized, flat, and fails to learn any underlying pattern. This leads to **High Bias**.

> **Summary:** Very low $K$ causes Overfitting; very high $K$ causes Underfitting. You must find a sweet spot in the middle using experimentation.

## 7. Failure Cases: When NOT to Use KNN
The instructor highlights **6 major limitations** where KNN should be avoided:

1. **Large Datasets (High Prediction Latency):** KNN is a "Lazy Learner." It does nothing during the training phase except store data points. All computations (calculating distances to every point and sorting them) happen during prediction. For a dataset with 500,000 points, predicting a single query point takes too long, making it unusable for low-latency web applications.
2. **High-Dimensional Data (Curse of Dimensionality):** When the number of features is very high (e.g., 500 features), the concept of distance breaks down in higher dimensions. Distance metrics become unreliable, causing KNN to fail.
3. **Sensitivity to Outliers:** If $K$ is set too low, random outliers can distort the decision boundary, carving out incorrect "pockets" of classes and leading to overfitting.
4. **Unscaled Features:** If data scaling is skipped, features with larger numeric scales will completely dominate the distance math, giving incorrect results.
5. **Imbalanced Datasets:** If $98\%$ of the dataset belongs to Class A and only $2\%$ belongs to Class B, any query point will naturally find more neighbors from Class A. The model becomes heavily biased toward the majority class.
6. **Lack of Interpretability (Inference):** KNN is a "Black Box" model. While it is great for *prediction* (telling you the final class), it is terrible for *inference*. It cannot explain *why* it made a choice or which feature (e.g., IQ or CGPA) was more important in making that prediction.
