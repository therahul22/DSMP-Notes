# Notes: Introduction to XGBoost

## 1. What is XGBoost?

* **Library vs. Algorithm:** XGBoost (**eXtreme Gradient Boosting**) is an optimized software library, not just a bare algorithm. It is built on top of the **Gradient Boosting Framework**.
* **Creator:** Created by **Tianqi Chen** (developed as a research project at the University of Washington).
* **Why Gradient Boosting?**
  * **Loss Function Flexibility:** Works with standard or custom loss functions.
  * **Versatility:** Handles classification, regression, ranking, and custom objective problems.
  * **High Performance:** Robust and handles missing data efficiently.

---

## 2. The 3 Pillars of XGBoost

### Pillar 1: Flexibility
* **Cross-Platform:** Works on Windows, Linux, and macOS.
* **Multi-Language Support:** Integrates with Python, R, C++, Java, Julia, Scala, and MATLAB.
* **Solves Diverse ML Problems:**
  * Binary & Multiclass Classification
  * Regression
  * Ranking (e.g., search engine relevance)
  * Time Series Forecasting
  * Anomaly Detection
* **Customization:** Allows user-defined loss functions and evaluation metrics.

---

### Pillar 2: Speed & Efficiency

> **How does parallel processing work if Boosting is sequential?**  
> Boosting builds trees *one after another* sequentially. However, XGBoost uses parallel processing **within each tree building step**—evaluating all features simultaneously to find the best split points.

* **Column Block Structure:** Data is stored in sorted, column-wise blocks in memory, making feature-level parallel searching fast and efficient.
* **Cache Awareness:** Data is structured so the CPU cache (L1/L2) can access split values rapidly without waiting on main memory.
* **Out-of-Core Computing:** Enables training on datasets larger than RAM by reading data in chunks from the hard drive.
* **Distributed Computing:** Scales across cluster environments (Hadoop, Spark, Dask).
* **GPU Support:** Accelerates tree building using GPU hardware (e.g., setting `tree_method='hist'` / `gpu_hist`).

---

### Pillar 3: Model Performance & Accuracy

| Technique | How It Works |
| :--- | :--- |
| **Regularized Objective** | Includes built-in $L_1$ (Lasso) and $L_2$ (Ridge) regularization to prevent overfitting. |
| **Sparsity-Aware Split Finding** | Automatically learns the best default path for missing values or sparse data. |
| **Approximate Tree Learning** | Uses a **Weighted Quantile Sketch** to bucket continuous feature values into bins, drastically reducing calculation time on large datasets. |
| **Max-Depth Pruning** | Prunes trees backwards (bottom-up) past a user-set depth whenever a split doesn't meet the required minimum gain threshold ($\gamma$). |
