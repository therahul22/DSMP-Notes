# 🧠 Embedded Methods & Recursive Feature Elimination

## 1. What are Embedded Methods?
**Embedded methods** are feature selection techniques that perform feature selection natively as an inherent part of the model construction process. 

> **The Intuition:** Instead of filtering features before training (Filter Methods) or running thousands of training loops on external subsets (Wrapper Methods), embedded methods look inside the model *during* training to see which parameters are actually doing the heavy lifting. They capture feature interactions like wrappers while remaining computationally efficient like filters.

### The Universal Access Keys: Internal Attributes
Any machine learning algorithm that exposes one of these two internal attributes during training can be leveraged for embedded feature selection:

1. **`coef_` (Coefficients):** Used by parametric/linear algorithms. The magnitude of the coefficient directly reflects the feature's weight or impact on the target variable.
   * *Examples:* Linear Regression, Logistic Regression, Ridge, Lasso, and ElasticNet.
2. **`feature_importances_`:** Used by tree-based non-linear ensemble algorithms. It calculates feature utility using metrics like **Mean Decrease Impurity (MDI)**.
   * *Examples:* Decision Trees, Random Forests, and Gradient Boosting models.

---

## 2. Linear Regression Coefficients & Classical Assumptions
In a classical linear regression equation, the learned weights ($\beta_i$) function as the feature importance metric. However, for these coefficients to be reliable for feature selection, the dataset must satisfy five fundamental statistical assumptions:
* **Linearity:** The relationship between the independent features and target variable must be linear.
* **Independence:** Individual observations and their resulting error residuals must be completely independent of one another.
* **Homoscedasticity:** The variance of the error residuals must remain constant across all levels of the independent features.
* **Normality:** The error residuals must closely approximate a normal bell curve.
* **No Multicollinearity:** Input features must not be highly correlated with each other. If columns are highly correlated, it becomes incredibly difficult to properly interpret individual feature importance weights.

---

## 3. Regularized Linear Models (The Core Embedded Approach)
To circumvent the strict limitations of classical linear models and prevent overfitting, we introduce regularized linear models. These algorithms inject a mathematical **penalty term** directly into the loss function during training to suppress overly complex coefficients.



* 💡 **Interview Question: Why does Lasso create sparsity while Ridge does not?**
  * **Ridge Regression ($L_2$ Regularization):** Adds a penalty to the loss function. It shrinks the weights of unhelpful features close to zero, but mathematically **never forces them to exactly zero**. Thus, it minimizes complexity but does not execute strict feature selection.
  * **Lasso Regression ($L_1$ Regularization):** Adds a penalty that shrinks some coefficients **exactly to zero**. This eliminates completely irrelevant or redundant features from the equation, generating a **sparse matrix** and executing true feature selection.
  * **Elastic Net:** Implements a blended approach, incorporating penalties from both Lasso ($L_1$) and Ridge ($L_2$) simultaneously. This is particularly useful when handling multiple highly correlated features.

## 4. The Data Preprocessing Gold Standard
Because regularization models penalize the magnitude of coefficients, **you must standard-scale your data beforehand**. If features exist on different numeric scales, the variance will skew the regularizer's behavior.

### Correct Leakage-Free Workflow
* **`fit_transform()`**: Executed **only** on the training data (`X_train`). This calculates the sample mean ($\mu$) and standard deviation ($\sigma$) of the training split and applies the transformation.
* **`transform()`**: Executed on the test dataset (`X_test`). It uses the pre-calculated $\mu$ and $\sigma$ from the training split to scale test data without leaking future data distributions into the model.

```
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import Lasso

# Split the data safely
X_train, X_test, y_train, y_test = train_test_split(df.iloc[:, 0:-1], df.iloc[:, -1], test_size=0.2, random_state=1)

# Preserve column headers
cols = X_train.columns

# Standardize the feature spaces independently to prevent data leakage
scaler = StandardScaler()
X_train_scaled = pd.DataFrame(scaler.fit_transform(X_train), columns=cols)
X_test_scaled = pd.DataFrame(scaler.transform(X_test), columns=cols)

# Apply Lasso Embedded Selection (alpha controls penalty strength)
lasso = Lasso(alpha=0.1)
lasso.fit(X_train_scaled, y_train)
```

## 5. Hybrid/Wrapper Bridge: Recursive Feature Elimination (RFE)
**Recursive Feature Elimination (RFE)** is a hybrid wrapper method that leverages internal embedded model metrics (`coef_` or `feature_importances_`) to make strategic, greedy elimination decisions.

### The RFE Loop Algorithm
1. Train a baseline model using **all** features.
2. Query the model's internal `coef_` or `feature_importances_` values.
3. Identify the feature with the absolute lowest importance score and prune it from the dataset.
4. Re-train the model on the remaining features.
5. Repeat this pruning sequence recursively until you reach your target number of features ($k$).

```
import pandas as pd
from sklearn.ensemble import RandomForestClassifier
from sklearn.feature_selection import RFE

# Load dataset
url = "[https://gist.githubusercontent.com/curran/a08a1080b88344b0c8a7/raw/0e7a9b0a5d22642a06d3d5b9bcbad9890c8ee534/iris.csv](https://gist.githubusercontent.com/curran/a08a1080b88344b0c8a7/raw/0e7a9b0a5d22642a06d3d5b9bcbad9890c8ee534/iris.csv)"
df = pd.read_csv(url)

X = df.drop("species", axis=1)
y = df["species"]

# Initialize internal engine model
model = RandomForestClassifier()

# Initialize RFE step loop to recursively eliminate until 1 best feature remains
rfe = RFE(estimator=model, n_features_to_select=1)
rfe.fit(X, y)

# Output results (1 = top priority feature)
print("Feature elimination ranking:")
for i, feature in enumerate(X.columns):
    print(f"{feature}: {rfe.ranking_[i]}")
```

> 💡 **Best Practice Note:** Instead of guessing a fixed target number of features for `n_features_to_select`, use **`RFECV`** (Recursive Feature Elimination with Cross-Validation) to automatically find the mathematically optimal number of features based on performance scores.

## 6. Comprehensive Trade-offs of Embedded Methods

### Advantages
* **High Accuracy:** Unlike filter methods, embedded approaches explicitly account for feature interactions during model training.
* **High Efficiency:** Vastly faster than standard wrappers. Instead of brute-forcing thousands of arbitrary column combinations, embedded methods complete feature selection over a single or minimal number of model fits.
* **Inherent Regularization:** The built-in mathematical penalty structures naturally combat overfitting out of the box.

### Disadvantages
* **Model Specificity:** The feature selection mapping is deeply linked to the training algorithm. Features selected via Lasso are not guaranteed to be optimal if you swap the backend to a Random Forest or Support Vector Machine.
* **Hyperparameter Tuning Dependency:** Requires diligent tuning of regularization strengths (such as the alpha value in Lasso/Ridge) to achieve clean feature selection.
* **Susceptibility to Data Instability:** Small, minor variations in the input data distribution can drastically alter tree splits or weight optimization paths, resulting in a completely different set of selected features.

## 7. Master Feature Selection Reference Matrix

| Selection Tool | Best Use Case | Captures Interactions? | Computational Cost | Primary Drawback / Constraint |
| :--- | :--- | :--- | :--- | :--- |
| **Variance Threshold** | Early pipeline preprocessing; eliminating dead columns. | No | Extremely Low | Completely blind to target variable relationships. |
| **Pearson Correlation** | Dropping redundant multi-collinear pairs. | No | Low | Restricted solely to straight linear lines. |
| **Chi-Square ($\chi^2$)** | Categorical Features vs. Categorical Target. | No | Low | Demands data binning for continuous features. |
| **ANOVA ($F$-Test)** | Categorical Features vs. Continuous Target. | No | Low | Assumes clean normal data distributions. |
| **Mutual Information** | Capturing hidden non-linear target shapes. | No | Moderate | Prone to keeping highly redundant features. |
| **Exhaustive Selection** | Small feature spaces where finding the best global set matters. | Yes | Exponentially High | Suffers intensely from the curse of dimensionality. |
| **Sequential (SFS/SBE)** | Approximating optimal subsets when resource limits apply. | Yes | High | Greedy optimization; can miss global optimums. |
| **Lasso ($L_1$) Regression** | Creating highly sparse, interpretable linear models. | Yes | Low (Embedded) | Completely model-dependent; requires rigorous scaling. |
| **Random Forest (MDI)** | Pulling stable ensemble rankings for tree models. | Yes | Low (Embedded) | Can drift or vary if the data changes slightly. |
| **RFE / RFECV** | Automating wrapper loops using native model judgements. | Yes | Moderate | Dependent on the performance of the core estimator. |
