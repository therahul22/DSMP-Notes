# K-Nearest Neighbors (KNN) Lecture Notes

## 1. Introduction & Intuition of KNN
* **Real-World Logic:** The core logic of the KNN algorithm is deeply inspired by real-world behavior. A famous quote by entrepreneur Jim Rohn perfectly captures its essence: *"You are the average of the five people you spend the most time with."*
* **Core Principle:** KNN operates on a very simple premise—**you are like your neighbors**. 

### The Problem Setup
* Imagine a dataset of $1,000$ students containing their **CGPA**, **IQ**, and whether they got **Placed (1) or Not Placed (0)**.
* The goal is to build a Machine Learning model that can predict whether a new student will get placed based on their CGPA and IQ.

---

## 2. Geometric Understanding: How KNN Works
When visualized in a 2D space (with CGPA on one axis and IQ on the other):
1. **Plot the Data:** Existing students are plotted using two colors (e.g., Blue for Placed, Pink for Not Placed).
2. **Choose the Value of $K$:** You must decide on a value for $K$ (e.g., $K = 3$), which means the algorithm will consider the 3 nearest neighbors.
3. **Calculate Distances:** When a new student (query point) arrives, the algorithm calculates its distance from **all** existing points in the dataset. Usually, **Euclidean distance** is used.
4. **Sort and Select:** All calculated distances are sorted in ascending order, and the top $K$ (closest) points are selected.
5. **Majority Count (Voting):** A democracy-style vote is conducted among the $K$ neighbors. Whichever class has the majority becomes the predicted label for the new point. 
   * *Example:* If among 3 neighbors, two say "Placed (1)" and one says "Not Placed (0)", the final prediction is "Placed (1)".

## 3. Code Implementation & Data Preprocessing
The instructor demonstrates KNN using a **Breast Cancer Dataset** to classify tumors.

### Essential Steps:
* **Feature Dropping:** Irrelevant columns like `ID` and empty columns were dropped.

## 4. How to Choose the Best Value of $K$?
The performance of KNN changes significantly based on the value of $K$. There are two primary approaches to finding the optimal $K$:

### A. Heuristic Approach
* A common rule of thumb used by researchers is to set $K = \sqrt{n}$, where $n$ is the total number of observations (rows) in your data.
* **Tip:** It is often recommended to choose an **odd number** for $K$ to avoid tie breaks (conflicts) during the majority voting phase.

### B. Experimental Approach (Hyperparameter Tuning)
* Run a loop testing multiple values of $K$ (e.g., $K = 1$ to $15$).
* For each value, train a KNN model and calculate its accuracy score.
* Plot $K$ values on the X-axis and Accuracy on the Y-axis. Choose the $K$ value that yields the highest accuracy (in the video's example, $K = 3$ gave the best results).

## 6. Overfitting and Underfitting in KNN
Changing the value of $K$ drastically alters the behavior of the decision boundary:

### Small $K$ Values (e.g., $K = 1$) $\rightarrow$ Overfitting
* The model looks only at its absolute closest neighbor.
* The decision boundary becomes highly complex, jagged, and memorizes minor noise/outliers in the data.
* This leads to **High Variance** (performing well on training data but poorly on unseen test data).

### Large $K$ Values (e.g., $K = \text{Total Dataset Size } n$) $\rightarrow$ Underfitting
* If $K = 200$ (for a dataset of 200 points), the model will always look at the entire dataset for every single query point.
* The majority vote will **always** be won by whichever class is dominant in the overall dataset.
* The decision boundary becomes overly generalized, flat, and fails to learn any underlying pattern. This leads to **High Bias**.

> **Summary:** Very low $K$ causes Overfitting; very high $K$ causes Underfitting. You must find a sweet spot in the middle using experimentation.

---

## 7. Failure Cases: When NOT to Use KNN
The instructor highlights **6 major limitations** where KNN should be avoided:

1. **Large Datasets (High Prediction Latency):** KNN is a "Lazy Learner." It does nothing during the training phase except store data points. All computations (calculating distances to every point and sorting them) happen during prediction. For a dataset with 500,000 points, predicting a single query point takes too long, making it unusable for low-latency web applications.
2. **High-Dimensional Data (Curse of Dimensionality):** When the number of features is very high (e.g., 500 features), the concept of distance breaks down in higher dimensions. Distance metrics become unreliable, causing KNN to fail.
3. **Sensitivity to Outliers:** If $K$ is set too low, random outliers can distort the decision boundary, carving out incorrect "pockets" of classes and leading to overfitting.
4. **Unscaled Features:** If data scaling is skipped, features with larger numeric scales will completely dominate the distance math, giving incorrect results.
5. **Imbalanced Datasets:** If $98\%$ of the dataset belongs to Class A and only $2\%$ belongs to Class B, any query point will naturally find more neighbors from Class A. The model becomes heavily biased toward the majority class.
6. **Lack of Interpretability (Inference):** KNN is a "Black Box" model. While it is great for *prediction* (telling you the final class), it is terrible for *inference*. It cannot explain *why* it made a choice or which feature (e.g., IQ or CGPA) was more important in making that prediction.

# K-Nearest Neighbors (KNN) Lecture Notes - Part 2

## 1. Hyperparameters in KNN
Hyperparameters are configurations that you set before training the model to control how the algorithm behaves. In KNN, the two primary hyperparameter variations are:

### A. Uniform KNN (Standard KNN)
* Every neighbor within the chosen $K$ pool gets an **equal vote** (weight = 1), regardless of how close or far they are from the query point.

### B. Weighted KNN
* Instead of equal votes, neighbors are assigned weights based on their distance from the query point.
* **Weight Formula:** $W = \frac{1}{\text{distance}}$
* **Logic:** A neighbor that is very close to the query point will have a small distance, resulting in a **larger weight (more voting power)**. A neighbor farther away will have a larger distance, resulting in a **smaller weight (less voting power)**.

#### Weighted KNN Classification Example ($K=5$):
Suppose a query point has 5 nearest neighbors with the following classes and distances:
* **Neighbor 1 (Red):** Distance = 0.2 $\rightarrow$ Weight = $\frac{1}{0.2} = 5$
* **Neighbor 2 (Red):** Distance = 0.5 $\rightarrow$ Weight = $\frac{1}{0.5} = 2$
* **Neighbor 3 (Green):** Distance = 1.0 $\rightarrow$ Weight = $\frac{1}{1.0} = 1$
* **Neighbor 4 (Green):** Distance = 2.0 $\rightarrow$ Weight = $\frac{1}{2.0} = 0.5$
* **Neighbor 5 (Green):** Distance = 3.0 $\rightarrow$ Weight = $\frac{1}{3.0} = 0.33$

**Voting Tally:**
* **Total Vote for Red:** $5 + 2 = 7$
* **Total Vote for Green:** $1 + 0.5 + 0.33 = 1.83$

> **Result:** Even though there are more Green neighbors (3 Green vs. 2 Red), **Red wins** because the Red points are much closer to the query point and carry higher weights.

## 2. Types of Distance Metrics
KNN relies entirely on calculating distances between data points. The choice of distance metric determines how "closeness" is measured:

### A. Minkowski Distance (The General Framework)
Minkowski distance is a generalized metric framework. By changing the value of the parameter $p$ ($p > 0$), it yields different distance types:

$$\text{Distance} = \left( \sum_{i=1}^{d} |x_{2i} - x_{1i}|^p \right)^{\frac{1}{p}}$$

### B. Euclidean Distance ($p = 2$ or $L_2$ Norm)
* Measures the straight-line distance between two points in space.
* **2D Formula:** $\text{Distance} = \sqrt{(x_2 - x_1)^2 + (y_2 - y_1)^2}$
* **$d$-Dimensional Formula:** $\text{Distance} = \sqrt{\sum_{i=1}^{d} (x_{2i} - x_{1i})^2}$

### C. Manhattan Distance ($p = 1$ or $L_1$ Norm)
* Also known as **Taxicab distance** or **Absolute distance**.
* Measures distance by traversing only along axis-parallel grid lines (like navigating city blocks).
* **Formula:** $\text{Distance} = \sum_{i=1}^{d} |x_{2i} - x_{1i}|$



#### Distance Metric Guidelines:
1. **Feature Scaling:** All features **must be on the same scale**; otherwise, features with larger numeric values will dominate the distance calculations.
2. **Curse of Dimensionality:** In very high-dimensional spaces (e.g., $d = 10,000$), Euclidean distance becomes highly compressed and unreliable. In these scenarios, **Manhattan distance ($p=1$) is generally more robust and reliable** than Euclidean distance ($p=2$).

---

## 3. Computational Complexity of Standard KNN
Standard KNN is computationally expensive, earning it the reputation of a **slow algorithm**.

### Time Complexity
* **Training Time:** $\mathcal{O}(1)$
  * Training is practically instantaneous because the algorithm simply saves the training data vectors into memory without building an explicit model.
* **Prediction Time:** $\mathcal{O}(n \cdot d)$
  * For *every single* query point, the model must calculate the distance to all $n$ training rows across $d$ features, and then sort those distances. If $n$ is very large (e.g., millions of rows), predictions become extremely sluggish.

### Space (Memory) Complexity
* **Storage Requirement:** $\mathcal{O}(n \cdot d)$
  * Because it is a lazy learner, the entire training dataset must reside inside RAM to process predictions, requiring massive memory footprints for large datasets.

---

## 4. Optimizing KNN: KD-Tree (K-Dimensional Tree)
To bypass the slow linear scanning ($\mathcal{O}(n)$) during prediction, advanced data structures like the **KD-Tree** are introduced.



### How it Works:
* A KD-Tree is a space-partitioning **Binary Search Tree** tailored for multi-dimensional geometric data.
* It systematically splits the feature space into distinct regions using axis-aligned lines (for 2D) or hyperplanes (for higher dimensions), alternating between features (e.g., splitting along the X-axis, then the Y-axis).
* By organizing data points hierarchically into a tree structure, the algorithm can quickly isolate which branch a query point $X_q$ falls into. It disregards entire sections of the dataset that are too far away without calculating distances to those individual points.

### Impact on Complexity:
* **Prediction Time Complexity:** Drops from $\mathcal{O}(n \cdot d)$ down to **$\mathcal{O}(d \cdot \log n)$**.
* Organizing data into a tree cuts down the lookup cost to a logarithmic scale ($\log_2 n$), making search times significantly faster for large baseline observation sets ($n$).
