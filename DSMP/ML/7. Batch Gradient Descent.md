# Batch Gradient Descent — Gradient Derivation Notes

## 1. The Setup

### Prediction (Hypothesis)

For a dataset with multiple features:

$$
\hat{y}_i = \beta_0 + \beta_1X_{i1} + \beta_2X_{i2} + \cdots + \beta_mX_{im}
$$

Where:
* $\beta_0$ = Intercept (Bias)
* $\beta_1, \beta_2, \dots, \beta_m$ = Feature weights (coefficients)

---

### Mean Squared Error (Loss Function)

The Mean Squared Error (MSE) measures the average squared prediction error over the entire dataset.

$$
L = \frac{1}{n}\sum_{i=1}^{n}(y_i-\hat{y}_i)^2
$$

Our goal is to minimize this loss by computing the gradient with respect to every parameter. This is done using the **Chain Rule**.

---

## 2. Deriving the Gradient for the Bias ($\beta_0$)

Start by differentiating the loss function.

$$
\frac{\partial L}{\partial \beta_0} = \frac{\partial}{\partial \beta_0} \left( \frac{1}{n} \sum_{i=1}^{n} (y_i-\hat{y}_i)^2 \right)
$$

Since differentiation distributes over summation:

$$
\frac{\partial L}{\partial \beta_0} = \frac{1}{n} \sum_{i=1}^{n} \frac{\partial}{\partial \beta_0} (y_i-\hat{y}_i)^2
$$

---

### Apply the Chain Rule

The Chain Rule states:
> Derivative of the outside function × derivative of the inside function.

**Outside Derivative:**
The outside function is $(y_i-\hat{y}_i)^2$. Differentiating gives:
$$
2(y_i-\hat{y}_i)
$$

**Inside Derivative:**
Expand the prediction equation inside the error term $(y_i - \hat{y}_i)$:
$$
\frac{\partial}{\partial \beta_0} \left( y_i - (\beta_0 + \beta_1X_{i1} + \beta_2X_{i2} + \dots) \right)
$$

Everything except $\beta_0$ is treated as a constant. Therefore:
$$
\frac{\partial}{\partial \beta_0}(y_i-\hat{y}_i) = -1
$$

---

### Final Gradient

Multiply the outside and inside derivatives:

$$
\frac{\partial L}{\partial \beta_0} = \frac{1}{n} \sum_{i=1}^{n} 2(y_i-\hat{y}_i)(-1)
$$

Therefore:

$$
\frac{\partial L}{\partial \beta_0} = -\frac{2}{n} \sum_{i=1}^{n}(y_i-\hat{y}_i)
$$

---

## 3. Deriving the Gradient for a Weight ($\beta_1$)

Start the same way:

$$
\frac{\partial L}{\partial \beta_1} = \frac{1}{n} \sum_{i=1}^{n} \frac{\partial}{\partial \beta_1} (y_i-\hat{y}_i)^2
$$

**Outside Derivative:**
Again, it is:
$$
2(y_i-\hat{y}_i)
$$

**Inside Derivative:**
Differentiate the error term with respect to $\beta_1$:
$$
\frac{\partial}{\partial \beta_1} \left( y_i - (\beta_0 + \beta_1X_{i1} + \beta_2X_{i2} + \dots) \right)
$$

Only the term containing $\beta_1$ remains, which is $-\beta_1X_{i1}$. The derivative is:
$$
-X_{i1}
$$

---

### Final Gradient

$$
\frac{\partial L}{\partial \beta_1} = \frac{1}{n} \sum_{i=1}^{n} 2(y_i-\hat{y}_i)(-X_{i1})
$$

Therefore:

$$
\frac{\partial L}{\partial \beta_1} = -\frac{2}{n} \sum_{i=1}^{n} (y_i-\hat{y}_i)X_{i1}
$$

---

## 4. General Gradient Formula

Since the derivation is identical for every feature:

$$
\frac{\partial L}{\partial \beta_m} = -\frac{2}{n} \sum_{i=1}^{n} (y_i-\hat{y}_i)X_{im}
$$

Where:
* $i$ = training example
* $m$ = feature number

---

## 5. Alternative Loss Function

Some books define the loss function as:

$$
L = \frac{1}{2}\sum_{i=1}^{n}(y_i-\hat{y}_i)^2
$$

Differentiating gives:

$$
\frac{\partial L}{\partial \beta_m} = -\sum_{i=1}^{n}(y_i-\hat{y}_i)X_{im}
$$

The factor of $\frac{1}{2}$ cancels the $2$ obtained from differentiating the square. Both formulations are mathematically equivalent.

---

## 6. Vectorization Intuition

The scalar gradient formula is:

$$
\frac{\partial L}{\partial \beta_m} = -\frac{2}{n} \sum_{i=1}^{n}(y_i-\hat{y}_i)X_{im}
$$

Instead of using nested Python loops, we use matrix multiplication.

* **Error Vector:** $(Y-\hat{Y})$ Shape: `(n × 1)`
* **Feature Matrix:** $X$ Shape: `(n × m)`
* **Transposed Feature Matrix:** $X^T$ Shape: `(m × n)`

### Matrix Multiplication

Compute:

$$
X^T(Y-\hat{Y})
$$

The dot product automatically performs every multiplication and summation simultaneously. The result is a gradient vector of shape `(m × 1)` containing gradients for every feature weight.

---

## Translating Math to Python Code

Here is how the vectorized mathematical model maps directly into a custom Python class using NumPy:

```python
import numpy as np

class BatchGDRegressor:
    def __init__(self, learning_rate=0.01, epochs=1000):
        self.lr = learning_rate
        self.epochs = epochs
        self.weights = None # Contains both beta_0 (intercept) and feature coefficients
        
    def fit(self, X, y):
        # n = number of samples, m = number of features
        n, m = X.shape
        
        # 1. Augmented Matrix Trick: Add a column of 1s to X for the intercept beta_0
        X_augmented = np.c_[np.ones(n), X]
        
        # 2. Initialize parameter vector beta with zeros (shape: m + 1, 1)
        self.weights = np.zeros((m + 1, 1))
        
        # Ensure y is a column vector for proper matrix math shapes
        y = y.reshape(-1, 1)
        
        # 3. Optimization Loop
        for _ in range(self.epochs):
            # Compute predictions vector (Y_hat = X . beta)
            y_pred = np.dot(X_augmented, self.weights)
            
            # Compute vectorized gradient: -(2/n) * X^T . (Y - Y_hat)
            gradients = -(2 / n) * np.dot(X_augmented.T, (y - y_pred))
            
            # Update all parameters simultaneously
            self.weights = self.weights - self.lr * gradients
            
    def predict(self, X):
        # Re-apply the column of 1s to match the augmented weights vector shape
        n = X.shape[0]
        X_augmented = np.c_[np.ones(n), X]
        return np.dot(X_augmented, self.weights)

    @property
    def intercept_(self):
        return self.weights[0][0]

    @property
    def coef_(self):
        return self.weights[1:].flatten()
```

## 7. Why Vectorization Is Faster

Instead of writing slow loops:

```python
for feature in features:
    for row in dataset:
        gradient += error * feature_value
```

We simply write:

```python
gradient = X.T @ (y - y_pred)
```

**Advantages:**
* No explicit Python loops
* Optimized BLAS/C implementation
* Much faster and cleaner code
* Standard practice in machine learning

---

## 8. Why Batch Gradient Descent Becomes Slow

Batch Gradient Descent computes the gradient using the **entire dataset** before every parameter update. If you have 100,000 rows, each iteration processes all 100,000 rows before updating the weights. As datasets grow, this becomes computationally expensive.

### Memory Constraints
Modern deep learning datasets often contain massive files (Images, Videos, Audio, Large text corpora). Loading the entire dataset into memory (RAM/VRAM) to perform a single batch update is often impossible.

---

## 9. The Solution

Instead of Batch Gradient Descent, modern ML uses:

### Stochastic Gradient Descent (SGD)
Uses **one training example** per update.
* **Advantages:** Very fast updates, easily escapes shallow local minima.
* **Disadvantage:** Very noisy optimization path.

### Mini-Batch Gradient Descent
Uses a small batch of samples (commonly 32, 64, 128, or 256).
* **Advantages:** Faster than Batch GD, stable convergence, highly optimized for GPUs.
* **Industry Standard:** This is the default optimization method for Deep Learning.

---

## Architectural Trade-offs in Gradient Descent Variants

| Metric / Feature | Batch Gradient Descent | Stochastic Gradient Descent (SGD) | Mini-Batch Gradient Descent |
| :--- | :--- | :--- | :--- |
| **Data per Update** | Entire dataset ($n$ rows) | 1 single row | A small batch (e.g., 32, 64, 128) |
| **Update Vectorization** | Fully vectorized across all $n$ samples | Vectorized only across features | Vectorized across the batch size |
| **Computational Speed** | Slow for large datasets | Rapid updates per row | Balanced and highly GPU-optimized |
| **Memory Blueprint** | High (Requires full matrix in memory) | Microscopic (1 row at a time) | Low to medium (Fits within cache) |
| **Convergence Path** | Smooth and deterministic | Highly erratic and noisy | Stable trajectory with slight noise |

### Hardware and Scalability Bottlenecks of Batch GD
1. **RAM OOM Errors:** Large enterprise scale production features cannot fit entirely into memory space during matrix multiplication ($X^T \cdot E$).
2. **Compute Inefficiency:** Calculating millions of row transformations just to take one step down the optimization curve stalls execution, which is why Deep Learning architectures default exclusively to Mini-Batch schemes.
