# Assumptions in LR, Log-Odds, Polynomial Boundaries & Regularization

## 1. Assumptions of Logistic Regression
While Logistic Regression is versatile, it relies on several core mathematical assumptions to ensure reliable inference and model performance:

1. **Binary Dependent Variable:** For standard binary logistic regression, the target variable $Y$ must be categorical with exactly two outcomes (e.g., $1$ vs $0$, Spam vs. Not Spam). Mathematically, $Y$ follows a **Bernoulli Distribution**.
2. **Independence of Observations:** Individual data rows/samples must be independent of one another. The outcome of one student's placement should not directly dictate or alter another's.
3. **Linearity of Log-Odds:** Unlike Linear Regression (which assumes a direct linear relationship between $X$ and $Y$), Logistic Regression assumes that input features $X$ are **linearly related to the Log-Odds** ($\log(\text{Odds})$) of the outcome variable.
4. **Absence of Multicollinearity:** Independent variables ($X_1, X_2, \dots$) should not be highly correlated with each other. Extreme correlation makes the weight coefficients ($\beta$) unstable and difficult to interpret.
5. **Large Sample Size:** Logistic Regression relies on Maximum Likelihood Estimation (MLE), which requires adequate sample sizes to converge accurately. 
   * **Rule of Thumb:** You need at least **10 cases of the least frequent outcome** per feature parameter.
   * *Example:* For $5$ independent features where the minority class occurs $10\%$ of the time ($p = 0.10$), the minimum required dataset size is:
     $$\text{Min Sample Size} = \frac{10 \times 5}{0.10} = 500 \text{ rows}$$

## 2. Odds and Log-Odds Interpretation

### What are Odds?
The **Odds** of an event represents the ratio of the probability that the event **occurs** ($p$) to the probability that it **does not occur** ($1 - p$):

$$\text{Odds} = \frac{p}{1 - p}$$

* If $p = 0.8$ (80% chance of success): $\text{Odds} = \frac{0.8}{0.2} = 4$ (Event is 4 times more likely to happen than not).
* $\text{Odds} > 1 \implies$ Event is more likely to happen than not.
* $\text{Odds} < 1 \implies$ Event is less likely to happen than not.

---

### Algebraic Derivation: Proving Linearity of Log-Odds
We know that Logistic Regression models probability $p$ using the Sigmoid equation:
$$p = \frac{1}{1 + e^{-\beta X}}$$

Let's rearrange this formula step-by-step to isolate $\beta X$:

1. Invert both sides:
   $$1 + e^{-\beta X} = \frac{1}{p}$$

2. Subtract $1$ from both sides:
   $$e^{-\beta X} = \frac{1}{p} - 1 = \frac{1 - p}{p}$$

3. Take the reciprocal of both sides:
   $$e^{\beta X} = \frac{p}{1 - p}$$

4. Apply the natural logarithm ($\ln$ or $\log$) to both sides:
   $$\log\left(\frac{p}{1 - p}\right) = \log(e^{\beta X})$$

5. The $\log$ and exponential cancel out:
   $$\log\left(\frac{p}{1 - p}\right) = \beta X$$

$$\log(\text{Odds}) = \beta_0 + \beta_1 X_1 + \beta_2 X_2 + \dots + \beta_k X_k$$

> **Takeaway:** This proves why Logistic Regression is considered a **linear model**. While $p$ has a non-linear $S$-shaped relationship with $X$, the **Log-Odds** ($\log(\text{Odds})$) has a strictly **linear relationship** with $X$.

## 3. Polynomial Features: Handling Non-Linear Boundaries
When data classes are not linearly separable (e.g., concentric circles or interlocking crescent moons):

* A standard linear logistic model ($z = \beta_0 + \beta_1 X_1 + \beta_2 X_2$) can only draw a straight line, leading to severe **Underfitting**.
* **Solution:** Transform input features by adding higher-degree polynomial terms (e.g., $X_1^2, X_2^2, X_1 X_2$):
  $$z = \beta_0 + \beta_1 X_1 + \beta_2 X_2 + \beta_3 X_1^2 + \beta_4 X_2^2 + \beta_5 (X_1 X_2)$$

### Polynomial Trade-Off
* **Small Degree:** Results in a simple boundary $\implies$ Risks **Underfitting**.
* **High Degree:** Results in a complex, wiggly boundary $\implies$ Risks **Overfitting** (learning noise instead of patterns).

---

## 4. Regularization in Logistic Regression
To prevent overfitting caused by high-degree polynomial features or overly large weights ($\beta$), we add a **penalty term** to the loss function.

### Types of Regularization

#### 1. L1 Regularization (Lasso)
Adds a penalty equal to the **absolute sum** of parameter weights:
$$\text{Penalty} = \lambda \sum_{j=1}^{k} |\beta_j|$$
* **Key Feature:** Forces unhelpful or redundant feature weights directly to **exact zero** ($\beta_j = 0$).
* **Use Case:** Performs implicit **Feature Selection**, producing sparse models.

#### 2. L2 Regularization (Ridge)
Adds a penalty equal to the **squared sum** of parameter weights:
$$\text{Penalty} = \lambda \sum_{j=1}^{k} \beta_j^2$$
* **Key Feature:** Shrinks weights evenly toward zero, but rarely sets them to exact zero.
* **Use Case:** Prevents any single feature from dominating the model decisions.

#### 3. Elastic Net
A hybrid approach that combines both L1 and L2 penalties using a mixing ratio hyperparameter.

---

### The Hyperparameter $\lambda$ (Lambda)
The regularization strength is controlled by the hyperparameter $\lambda$:
* **High $\lambda$:** Strong penalty $\implies$ Shrinks parameters heavily $\implies$ Model becomes simpler (Risks **Underfitting**).
* **Low $\lambda$:** Weak penalty $\implies$ Allows larger weights $\implies$ Model becomes complex (Risks **Overfitting**).
* *Note in Scikit-Learn:* Scikit-Learn uses $C = \frac{1}{\lambda}$. So, a **smaller $C$** means stronger regularization, while a **larger $C$** means weaker regularization.
