# Feature Selection

## 1. Core Concepts: Why Do Feature Selection?
Features are simply the input columns in our dataset. While it seems like more data is always better, having too many columns actually degrades model performance after a certain point.

* **The Curse of Dimensionality:** As the number of features increases, the data space grows exponentially and becomes very sparse (empty). This sparsity degrades model performance.
* **Computational Complexity:** More features mean training takes vastly more time and processing power. Dropping columns simplifies this.
* **Interpretability:** It's easier to explain a model built on 5 key factors to stakeholders than one built on 500 messy columns.

## 2. What are Filter-Based Methods?
Filter methods use **statistical measures** to score each feature completely independently of the machine learning model. 

> **The Intuition:** Think of it like a sieve. You look at each column one by one, check its statistical properties, and either keep it or filter it out before any training even begins.

### General Pros & Cons of Filter Methods
* 👍 **Pros:** Very simple to understand, incredibly fast, highly scalable for massive datasets, and great as a quick pre-processing step.
* 👎 **Cons:** **Model Agnostic** (ignores the actual ML model being used), **Ignores Feature Interactions** (evaluates one-by-one, so it misses pairs that are powerful *together*), and requires arbitrary thresholds.

---

## 3. Filter Method Plan of Action
When cleaning a dataset using filters, we generally follow these progressive steps:

### Step 1: Remove Duplicate Features
If two columns contain identical values, one is completely redundant and must be deleted.

* **Implementation Trick:** Convert column values to hashes/bytes to quickly find matches using a dictionary.
```python
def get_duplicate_columns(df):
    duplicate_columns = {}
    seen_columns = {}
    for column in df.columns:
        current_column = df[column]
        try:
            current_column_hash = current_column.values.tobytes()
        except AttributeError:
            current_column_hash = current_column.to_string().encode()

        if current_column_hash in seen_columns:
            if seen_columns[current_column_hash] in duplicate_columns:
                duplicate_columns[seen_columns[current_column_hash]].append(column)
            else:
                duplicate_columns[seen_columns[current_column_hash]] = [column]
        else:
            seen_columns[current_column_hash] = column
    return duplicate_columns
```

### Step 2: Variance Threshold (Target Agnostic)
Filters out columns that don't change much across rows.
* **Constant Features:** A column where *every* single row has the exact same value (Variance = 0). It provides zero predictive power.
* **Quasi-Constant Features:** Columns where, for example, 995 out of 1000 rows have a `1` and only 5 rows have a `0`. The variance is near 0, so we drop it based on a chosen threshold (e.g., $0.05$ or $0.1$).
* ⚠️ **CRITICAL NOTE:** Always **normalize/standardize** data before checking variance! If one column ranges from 0–1 and another ranges from 0–100,000, the second one will naturally have a massive variance simply because of its scale.

### Step 3: Correlation (Pearson Coefficient)
Measures the strength of linear relationships. We look for two things here:
1. **Feature-to-Target ($X_i \rightarrow Y$):** We want a high correlation (positive or negative) because it means the feature has strong predictive power.
2. **Feature-to-Feature ($X_i \leftrightarrow X_j$):** High correlation here means **Multi-collinearity**. If two features tell the same story (e.g., longitude and latitude coordinates of a fixed area), we can safely drop one to save computation space.
* ⚠️ **Drawbacks:** Completely misses non-linear relationships, is highly sensitive to outliers, and requires manual threshold setting.

### Step 4: ANOVA (Analysis of Variance)
Used when the input feature ($X$) is **Numerical** and the target variable ($Y$) is **Categorical**.
* It performs a statistical hypothesis test to evaluate if the means of the numerical feature vary significantly across different target classes.
* Outputs an **F-statistic** and a **p-value**. A high F-statistic / low p-value ($< 0.05$) means we reject the null hypothesis, proving the feature is highly relevant to separating the classes.
* ⚠️ **Drawbacks:** Assumes normal distribution of data, assumes equal variances across groups (homoscedasticity), and is heavily altered by outliers.

### Step 5: Chi-Square Test ($\chi^2$)
Used strictly when **both** the input feature ($X$) and the target variable ($Y$) are **Categorical** (e.g., Sex vs. Survival status on the Titanic).
* It compares your **Observed values** in a contingency table against the **Expected values** if no relationship existed.
* $$\chi^2 = \sum \frac{(\text{Observed} - \text{Expected})^2}{\text{Expected}}$$
* A high Chi-Square score means the feature and target are heavily dependent on each other, making it an excellent feature to keep.
* ⚠️ **Drawbacks:** Cannot be used on continuous numerical variables unless you bin/discretize them first (which loses data precision), and requires a large enough sample size per category (typically $\ge 5$) to be statistically reliable.

### Step 6: Mutual Information (MI)
Mutual Information is a fundamental quantity in information theory used to measure the statistical dependency between two variables. It quantifies the exact amount of information you can obtain about one random variable (like the target $Y$) simply by observing another variable (like a feature $X$).

#### The Mathematical Foundation
For discrete variables, Mutual Information is defined as:

$$MI(X, Y) = \sum_{x \in X} \sum_{y \in Y} p(x, y) \log \left[ \frac{p(x, y)}{p(x) p(y)} \right]$$

Where the components stand for:
* **$p(x, y)$ (Joint Probability):** The probability of two or more events happening simultaneously at the same time. For instance, the probability that a passenger is both Male ($X$) AND did not survive ($Y$).
* **$p(x)$ and $p(y)$ (Marginal Probabilities):** The probability of an event occurring completely regardless of the outcome of the other event. It is found by summing or integrating out the other variable.

> **The Intuition:** The equation compares the joint probability $p(x, y)$ against the product of the independent marginal probabilities $p(x)p(y)$. If $X$ and $Y$ are completely independent, then $p(x, y) = p(x)p(y)$, which makes the fraction $\frac{1}{1}$. Because $\log(1) = 0$, the overall Mutual Information becomes $0$.

---

#### Core Properties for Feature Selection
* **Non-Negative:** MI scores are always $\ge 0$. A value of exactly zero proves that the feature and target are completely independent.
* **Symmetric:** The information value flows equally both ways: $MI(X, Y) = MI(Y, X)$.
* **Captures Any Dependency:** Unlike Pearson correlation (which strictly looks for straight lines), Mutual Information can capture **any** statistical dependency, including complex non-linear or quadratic curves.

---

#### Disadvantages of Mutual Information

1.  **Estimation Difficulties:** Calculating true MI from real-world data is highly challenging when dealing with high-dimensional spaces or sparse data with small sample sizes. It forces reliance on density estimation or binning strategies that are highly sensitive to user parameters.
2.  **Requires Large Datasets:** When working with restricted or small sample sizes, MI calculations tend to become noisy, unstable, and less reliable, occasionally leading to false assumptions about data dependencies.
3.  **Highly Computationally Intensive:** Evaluating the joint and marginal probabilities across thousands of continuous features demands heavy computational resources and time.
4.  **Trouble with Continuous Features:** While it theoretically accommodates continuous data, accurate continuous density estimation is an incredibly complex task in practice.
5.  **No Direct Indication of Relationship Nature:** MI will tell you *that* a strong relationship exists, but it provides no details on *how* they relate (e.g., whether it is linear, quadratic, or exponential). 
6.  **Blind to Redundancy:** MI is a univariate filter metric. If feature $X_1$ and feature $X_2$ are perfectly correlated duplicates, they will both get an identical high MI score relative to the target. Because the filter evaluates them independently, it will erroneously select both redundant features.     
---

## 4. Quick-Reference Selection Guide
Use this mental matrix when picking your statistical filter method based on data types:

| Input Feature ($X$) | Target Variable ($Y$) | Recommended Filter Tool |
| :--- | :--- | :--- |
| **Continuous / Numerical** | **Continuous / Numerical** | Pearson Correlation Coefficient |
| **Continuous / Numerical** | **Categorical** | ANOVA ($F$-test) |
| **Categorical** | **Categorical** | Chi-Square Test ($\chi^2$) |

# Wrapper-Based Feature Selection

## 1. Code Implementations & Mechanics

Unlike filter methods that rely on pure data statistics, wrapper methods train a machine learning algorithm iteratively on different subsets to identify the highest-performing combinations.

### The Standard Code Workflow

1. **Establish a Baseline:** Train a model using all features to find your starting benchmark score.
2. **Feature Scale:** Always standardize your variables (`StandardScaler`) when working with models sensitive to scale, like linear or logistic regression.
3. **Search Subsets:** Run the selection algorithm (`mlxtend` or `sklearn`).
4. **Evaluate & Transform:** Filter the dataset to include only the selected features, then verify if your test score improved.

---

## 2. Exhaustive Feature Selection (EFS)

This is the brute-force approach. It evaluates every possible combination of features up to your designated maximum.

### Classification Example: Iris Dataset

**The Target:** Classifying Iris species using 4 features (`sepal_length`, `sepal_width`, `petal_length`, `petal_width`).

**The Math:** Testing up to 4 features generates exactly:

$$
2^4 - 1 = 15
$$

unique combinations.

```python
from mlxtend.feature_selection import ExhaustiveFeatureSelector as EFS
from sklearn.linear_model import LogisticRegression

lr = LogisticRegression()

# Max_features=4 means evaluate all subsets of size 1, 2, 3, and 4
sel = EFS(
    lr,
    max_features=4,
    scoring='accuracy',
    cv=5
)

model = sel.fit(df.iloc[:, :4], df['species'])

print("Best Score:", model.best_score_)
print("Best Features:", model.best_feature_names_)
```

### Key Insights from the Iris Output Matrix

- **1 Feature Subsets:** `petal_width` alone achieves an average accuracy of **96%**, whereas `sepal_width` alone yields only **56%**.
- **The Winner:** The top combination uses **3 features**:
  `('sepal_width', 'petal_length', 'petal_width')`,
  reaching an accuracy of **97.33%**.
- **Redundancy Detection:** Adding the 4th feature (`sepal_length`) results in the exact same score (**97.33%**). This explicitly shows that `sepal_length` adds zero predictive value once the other three are present.

### Regression Example: Boston Housing Dataset

When working with regression problems, your feature combinations grow exponentially. With **13 base features**, testing all subsets yields:

$$
2^{13} - 1 = 8,\!190
$$

unique combinations.

### The Baseline Performance (All 13 Features)

```text
Training R² Score: 0.7025
Testing R² Score:  0.6515
```

### Fixing R² with Adjusted R²

Standard $R^2$ will mathematically increase (or stay the same) whenever you add a new feature, even if that feature is useless. To avoid this trap, we calculate **Adjusted $R^2$**, which penalizes the score based on the number of features added:

$$
Adjusted\ R^2 =
1 -
\frac{(1-R^2)(N-1)}
{N-K-1}
$$

Where:

- $N$ = number of rows (**404 observations**)
- $K$ = number of features

```python
def adjust_r2(r2, num_examples, num_features):
    coef = (num_examples - 1) / (num_examples - num_features - 1)
    return 1 - (1 - r2) * coef
```

### Post-EFS Performance (Top 10 Features)

By sweeping through all combinations and sorting by `adjusted_r2`, EFS uncovers that dropping **3 specific columns** optimizes performance.

**Best Features Selected:** Indices `(0, 1, 4, 5, 7, 8, 9, 10, 11, 12)`

```text
Optimized Training R²: 0.7100
Optimized Testing R²:  0.7205  <-- Huge jump! Overfitting was eliminated.
```

## 3. Stepwise Sequential Selection

Because checking **8,190 combinations** is slow, we use greedy step-by-step estimators instead. These follow an arithmetic progression, requiring only:

$$
\frac{n(n+1)}{2}
$$

evaluations.

For **13 features**, that is only **91** total model checks instead of **8,190**.

### Sequential Forward vs. Backward Choice

- **mlxtend implementation:** Uses `SequentialFeatureSelector`. You toggle between Forward Selection and Backward Elimination using the `forward` boolean argument.
- **sklearn implementation:** Provides a native `SequentialFeatureSelector` where you set the parameter `direction='forward'` or `direction='backward'`.

### Implementation with mlxtend

```python
from mlxtend.feature_selection import SequentialFeatureSelector as SFS
from sklearn.linear_model import LinearRegression

lr = LinearRegression()

# forward=True steps up from 0; forward=False steps down from all features
sfs = SFS(
    lr,
    k_features='best',
    forward=True,
    floating=False,
    scoring='r2',
    cv=5
)

sfs.fit(X_train, y_train)

print("Selected Feature Indices:", sfs.k_feature_idx_)
```

### Implementation with scikit-learn

If you need to strictly restrict your dataset to a fixed number of key features, `sklearn` makes it easy.

```python
from sklearn.feature_selection import SequentialFeatureSelector as SFS

# Force-select exactly the 5 best features using a forward search loop
sfs2 = SFS(
    model,
    n_features_to_select=5,
    direction='forward',
    scoring='r2',
    n_jobs=-1,
    cv=5
)

sfs2.fit(X_train, y_train)

print("Top 5 Feature Indices:", np.arange(X.shape[1])[sfs2.support_])

# Output: array([5, 7, 10, 11, 12])
```
