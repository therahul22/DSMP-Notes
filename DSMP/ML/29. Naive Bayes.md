## 🔢 1. The Numerical Underflow Problem

### The Problem
In standard Naive Bayes, we calculate the probability of a class by multiplying many small conditional probabilities together. Because probabilities are decimals between 0 and 1, multiplying dozens or hundreds of them results in a number that is extremely close to zero.

Early computers—and modern floating-point architectures—have precision limits. When a calculated value becomes smaller than the smallest positive number a machine can represent, **numerical underflow** occurs. The computer rounds the value down to absolute zero ($0$), destroying all precision and making it impossible to compare classes.

### The Solution: The Log Domain
To prevent numbers from collapsing to zero, we transform the calculation into the log domain. Applying logarithms changes multiplication into addition:

$$\log(A \times B) = \log(A) + \log(B)$$

Instead of maximizing a product of raw fractions, the model calculates the sum of log probabilities. Tiny fractional probabilities become manageable negative numbers (e.g., $-300$ instead of $10^{-130}$), keeping calculations safely within standard machine precision limits.

$$\hat{y} = \arg\max_{y_k} \left[ \log P(y_k) + \sum_{i=1}^{n} \log P(x_i \mid y_k) \right]$$

## 🧪 2. Zero-Probability & Laplace Additive Smoothing

### The Problem
If a query point contains a specific feature or word that never appeared alongside a class during training, its calculated probability becomes exactly 0. Because Naive Bayes multiplies all feature probabilities together, a single zero wipes out the entire calculation, returning a final probability of 0. If this happens across multiple classes, the model cannot compare them.

### The Solution
**Laplace Additive Smoothing** artificially adjusts the probability calculation by introducing a smoothing parameter, ensuring no probability ever drops to absolute zero.

### The General Smoothing Concept
$$P(x_i \mid y_k) = \frac{\text{Count}(x_i, y_k) + \alpha}{\text{Total Count of all features in } y_k + (n \times \alpha)}$$

> ⚠️ **Crucial Interview Note:** When implementing this equation, Laplace smoothing is **only applied to the conditional probabilities** ($P(F_1 \mid Y), P(F_2 \mid Y), \dots$). It is **never** applied to the base class prior $P(Y)$, because the overall count of the classes themselves will never be zero in your training set.

## ⚖️ 3. The Bias-Variance Tradeoff with Alpha ($\alpha$)

Instead of simply replacing a zero value with a hardcoded tiny number, using $\alpha$ allows us to control the **Bias-Variance Tradeoff**. Alpha serves as a tunable hyperparameter.

### Small $\alpha$ (or No Alpha) $\rightarrow$ High Variance (Overfitting)
* **Behavior**: The model relies almost entirely on the exact training data counts.
* **Scenario**: Imagine a dataset with 500 'yes' and 500 'no' outcomes. If a feature $f_1$ has 0 counts for the 'yes' class, even a minor change or outlier in the training data will wildly swing the output probabilities.
* **Result**: The model becomes overly sensitive to small fluctuations in the training dataset, creating a **high variance** model.

### Large $\alpha$ $\rightarrow$ High Bias (Underfitting)
* **Behavior**: As $\alpha$ grows very large, the actual count differences in the numerator and denominator lose their mathematical influence.
* **Convergence**: All individual conditional feature probabilities flatten out and **converge toward $0.5$**.
* **Result**: Because the features become equally probable ($0.5$ each), they cancel each other out during multiplication. The model stops listening to the features entirely and makes its final prediction based strictly on the base class distribution balance (e.g., if the data has 90% 'yes' and 10% 'no', it will just guess 'yes'). This creates a **high bias** model.

## 📈 4. Gaussian Naive Bayes

### When to Use
Use Gaussian Naive Bayes when your input features are purely **numerical/continuous** variables (such as age, salary, or test scores).

### The Math Formula
$$P(x_i \mid y = c) = \frac{1}{\sqrt{2\pi\sigma_c^2}} \exp\left(-\frac{(x_i - \mu_c)^2}{2\sigma_c^2}\right)$$

* **$\mu_c$**: The mean (average value) of the continuous feature $x_i$ computed exclusively for the training samples belonging to class $c$.
* **$\sigma_c^2$**: The variance (spread) of the continuous feature $x_i$ computed exclusively for the training samples belonging to class $c$.
* **$x_i$**: The incoming numerical value from the query point you want to predict.

### Why Laplace Smoothing is Omitted Here
Laplace smoothing is engineered specifically to fix zero-count issues in discrete categories. Because Gaussian Naive Bayes calculates its values from a continuous normal bell-curve function, the resulting PDF value **never touches absolute zero**. Since a zero value is structurally impossible, Laplace smoothing is completely unnecessary here.

## 🏷️ 5. Categorical Naive Bayes

### When to Use
Use Categorical Naive Bayes when your features consist entirely of distinct **categorical classes** (e.g., colors, explicit states, or defined types) where every feature is assumed to follow a multinomial distribution.

### The Math Formula
$$P(x_i = t \mid y = c; \alpha) = \frac{N_{tic} + \alpha}{N_c + \alpha n_i}$$

* **$P(x_i = t \mid y = c; \alpha)$**: The smoothed probability that feature index $i$ takes on a specific category value $t$, given that the class label is $c$.
* **$N_{tic}$**: The number of times category $t$ appears in the training samples for feature $i$ that belong to class $c$.
* **$N_c$**: The total number of training samples that belong to class $c$.
* **$\alpha$**: The smoothing hyperparameter.
* **$n_i$**: The **number of available categories** for that specific feature $i$ (e.g., if the feature is `Outlook` with values `[Sunny, Overcast, Rainy]`, then $n_i = 3$).

### Titanic Dataset Strategy (Finding the Terms)
Consider a subset tracking `gender` (M, F) and `pclass` (P1, P2, P3) vs `survived` (1 = Yes, 0 = No). To predict survival for a new query point—a Male passenger in P3:
* We need to calculate and compare $P(1 \mid \{M, P3\})$ and $P(0 \mid \{M, P3\})$.

To calculate the individual conditional probabilities, we **break the training dataset into two distinct parts** based on the class:

1. **The Survived Group ($y = 1$)**: Filter the data to look *only* at rows where `survived = 1`.
   * For $P(M \mid 1)$, calculate: $\frac{\text{Number of Males who survived } + \alpha}{\text{Total people who survived } + (\alpha \times n_{\text{gender}})}$ (where $n_{\text{gender}} = 2$).
   * For $P(P3 \mid 1)$, calculate: $\frac{\text{Number of P3 passengers who survived } + \alpha}{\text{Total people who survived } + (\alpha \times n_{\text{pclass}})}$ (where $n_{\text{pclass}} = 3$).
2. **The Dead Group ($y = 0$)**: Filter the data to look *only* at rows where `survived = 0`.
   * Follow the same isolated counting process using the total number of dead passengers as the baseline denominator context ($N_c$).

## 📊 6. Multinomial Naive Bayes

### When to Use
Multinomial Naive Bayes is designed for **discrete count metrics, frequencies, or fractional distributions**. Unlike Categorical NB, **each column independently represents a multinomial distribution** tracking how many times a item repeats.

### The Math Formula
$$P(x_i \mid y = c; \alpha) = \frac{N_{ci} + \alpha}{N_c + \alpha n}$$

* **$N_{ci}$**: The total frequency count of word/feature $i$ across all documents belonging to class $c$.
* **$N_c$**: The total count of **all words combined** across all documents belonging to class $c$ (referred to as `text_c`).
* **$\alpha$**: The smoothing hyperparameter.
* **$n$**: The total **vocabulary size** (the number of unique features/words tracked across the entire dataset, often denoted as $B$).

### Processing Multi-Word Frequencies (Exponentials)
When a new document is evaluated, words can appear multiple times. To account for this, the conditional probability of each word is **raised to the power of its frequency count** within that document. 

$$\text{Term Value} = (P(\text{word} \mid \text{Class}))^{\text{count}}$$

### Text Mining Example Walkthrough
Given a test document containing `chinese = 3` and `Beijing = 0`, with a vocabulary size of $n = 6$ and total class counts equal to $8$:
* For `Beijing`: The count is 0, evaluating to $(P(\text{Beijing} \mid Y))^0 = 1$ (neutral impact).
* For `chinese`: The count is 3, evaluating to $(P(\text{chinese} \mid Y))^3$, where $P(\text{chinese} \mid Y) = \frac{5 + 1}{8 + 6} = \frac{6}{14}$.

## 🔲 7. Bernoulli Naive Bayes

### When to Use
Use Bernoulli Naive Bayes when every feature follows a Bernoulli distribution—meaning the data is purely **binary (0 or 1)**. A classic example is a **Binary Bag of Words (BoW)**, where we only track *if it exists* (1) or *doesn't exist* (0).

### The Math Formula
$$P(x_i \mid y = c) = p_i^{x_i} (1 - p_i)^{1 - x_i}$$

* **$x_i$**: The binary value of the feature in the test document ($1$ if present, $0$ if absent).
* **$p_i$**: The probability of the feature appearing in class $c$, written as $P(\text{word} = 1 \mid c)$.
* **$(1 - p_i)$**: The probability of the feature *not* appearing in class $c$, written as $P(\text{word} = 0 \mid c)$.

### Key Interview Cruck: Handling Absent Features ($x_i = 0$)
* **The Rule:** **Bernoulli NB does not ignore absent words.** 
* **The Mechanism:** Instead of dropping it or marking it as 1 like Multinomial NB does ($P(\dots)^0 = 1$), if a test document does not contain a word (e.g., `Beijing = 0`), we explicitly calculate the **probability of that term NOT being in the data**: $(1 - P(\text{Beijing} = 1 \mid \text{Class}))$.
* **Why this matters:** Bernoulli NB penalizes the score if a word typical of a class is missing from the test document.

### Handling Zero Instances via Laplace
If a word appears 0 times out of the total documents for a class (e.g., a raw frequency of $0/3$), we apply Laplace smoothing to the baseline binary occurrence state:
$$P(\text{word} = 1 \mid c) = \frac{0 + 1}{3 + 2} = \frac{1}{5}$$
*(Note: The denominator adds $2$ because there are only two possible binary cases for each term: occurrence and non-occurrence).*
