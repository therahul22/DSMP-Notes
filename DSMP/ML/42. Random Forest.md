# Ensemble Learning & Random Forest

Ensemble learning combines predictions from multiple machine learning models to build a single model that is more accurate and robust than any individual base learner.

## 1. Understanding Bagging (Bootstrap Aggregating)

> **Core Concept:** Bagging is **not an algorithm itself**, but a **meta-technique** designed to reduce variance, improve model accuracy, and prevent overfitting.

### How It Works
1. **Sampling with Replacement (Bootstrapping):** Multiple subsets are generated from the original dataset by randomly selecting samples *with replacement*. 
2. **Train Base Models:** A separate model of the **same type** is trained independently on each random subset.
3. **Aggregate Results:**
   * **Classification:** Uses **Majority Voting** across all base models.
   * **Regression:** Uses the **Mean (Average)** of all predictions.

### Key Benefits
* **Bootstrapping:** Because each model gets a slightly different, random slice of the data, individual model errors balance out, reducing overall **variance** without increasing bias.
* **Sampling Flexibility:** Bootstrapping can be applied to **rows** (samples), **columns** (features), or **both simultaneously**.

---

## 2. Random Forest Intuition

Random Forest builds upon the bagging framework using **Decision Trees** as its core building block.

* **Wisdom of the Crowd:** Individual decision trees make different, uncorrelated errors. When their predictions are combined, the majority vote cancels out individual mistakes, yielding a reliable final prediction.
* **Bias-Variance Tradeoff:** Single decision trees typically have **Low Bias & High Variance** (they overfit easily). By ensembling them via Random Forest, the combined model achieves **Low Bias & Low Variance**.

---

## 3. The 2 Key Interview Questions: Bagging vs. Random Forest

### **Diff 1: Choice of Base Models**
* **Bagging:** Can use *any* base machine learning algorithm (e.g., KNN, SVM, Logistic Regression, or Decision Trees). However, all base models in a given bagging ensemble must be of the *same* type.
* **Random Forest:** The base model is **strictly Decision Trees**.

---

### **Diff 2: Node-Level vs. Tree-Level Feature Sampling**

> **Crucial Interview Point:** *"If we perform Bagging using Decision Trees as base models, is it a Random Forest?"*  
> **Answer:** **No!** The key difference lies in *how* feature sampling (column sampling) is applied.

| Feature Sampling Type | Bagging with Decision Trees | Random Forest |
| :--- | :--- | :--- |
| **Sampling Level** | **Tree-Level Sampling** | **Node-Level Sampling** |
| **Mechanism** | A subset of features (e.g., 2 out of 5 columns) is selected **once per tree**. The entire tree is built using only those chosen columns. | At **every single node** split within a tree, a new random subset of features is evaluated. |
| **Randomness & Diversity** | Lower structural diversity among trees. | Higher randomness, leading to significantly lower correlation between trees and better generalization performance. |

---

## 4. Feature Importance

* Random Forest automatically tracks feature importance during training based on how much a feature reduces impurity (Gini or Entropy) across splits.
* **Calculation:** The overall feature importance score is computed by taking the average importance of that feature **across all decision trees** in the forest.
* **Application:** This score can be leveraged directly for **feature selection** to drop irrelevant or noisy variables before deploying models.
