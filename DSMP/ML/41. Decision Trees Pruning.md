# Decision Trees: Feature Importance & Pruning

## 1. Feature Importance (Gini Importance)

Tree-based models calculate feature importance based on the **normalized total reduction of the criterion (impurity)** brought by a feature across all splits in the tree.

---

### A. Node Importance Formula (ni)

For any decision node t, its node importance ni_t measures how much a split reduces the overall impurity of the dataset:

$$ni_t = \frac{N_t}{N} \cdot \left[ I(t) - \left( \frac{N_{t,r}}{N_t} \cdot I(r) \right) - \left( \frac{N_{t,l}}{N_t} \cdot I(l) \right) \right]$$

#### Term-by-Term Explanation:
* **$N$**: Total number of samples in the entire dataset at the root.
* **$N_t$**: Number of samples reaching current node $t$.
* **${N_t}/{N}$**: Weight of current node $t$ relative to total dataset size.
* **${impurity}_t$**: Gini Impurity (or Entropy/MSE) at current node $t$ before splitting.
* **$N_{t,l}$ & $N_{t,r}$**: Number of samples going to the left child node ($l$) and right child node ($r$), respectively.
* **$I_{\text{left}}$ & $I_{\text{right}}$**: Impurity values of the left and right child nodes after split.
---

### B. Feature Importance Formula ($fi_k$)

To compute the final importance of feature $k$ ($fi_k$), sum up the node importances of all nodes split on feature $k$, then divide by the sum of node importances across **all decision nodes** in the tree:

$$fi_k = \frac{\sum_{j \in \text{nodes split on feature } k} ni_j}{\sum_{j \in \text{all decision nodes}} ni_j}$$

> **Example Tree Structure:**
> * Root Node split on **Sepal Length (SL)** $\rightarrow$ Node importance = $X$
> * Left Child Node split on **Sepal Width (SW)** $\rightarrow$ Node importance = $Y$
> * Right Child Node split on **Sepal Length (SL)** $\rightarrow$ Node importance = $Z$
>
> $$\text{Importance(SL)} = \frac{X + Z}{X + Y + Z} \quad \text{and} \quad \text{Importance(SW)} = \frac{Y}{X + Y + Z}$$

---

### C. Worked Example from Slide Data

Using the numerical values from the Iris Decision Tree diagram:

## 2. Pruning in Decision Trees

### Goal
To reduce **overfitting** and improve model generalization on unseen test data.

### Why Decision Trees Overfit
* **Algorithmic Nature:** Standard greedy Decision Trees do not have an internal stopping criterion by default.
* **Pure Leaf Creation:** The tree continues recursively splitting nodes until every terminal leaf contains a single sample or isolated pure class.
* **Noise Memorization:** Deep branches isolate outliers and noisy data points, creating unnecessarily complex decision boundaries.
* **Solution:** Cut unnecessary branches/nodes to simplify the tree structure.

---

## 3. Pre-Pruning (Early Stopping)

Pre-pruning halts the tree construction early during the training process as soon as specific threshold conditions are met.

### Key Pre-Pruning Strategies
1. **Maximum Depth (`max_depth`):** Caps the maximum depth (levels) of the tree. Once reached, growth stops.
2. **Minimum Samples Split (`min_samples_split`):** Requires a minimum number of samples in a node to permit further splitting.
3. **Minimum Samples Leaf (`min_samples_leaf`):** Ensures each resulting child leaf contains at least a minimum number of training instances.
4. **Maximum Leaf Nodes (`max_leaf_nodes`):** Hard caps the overall number of leaf nodes in the tree.
5. **Minimum Impurity Decrease (`min_impurity_decrease`):** Allows a split only if the reduction in impurity exceeds a defined threshold.
6. **Maximum Features (`max_features`):** Evaluates only a random subset of features for splitting at each node.

### Pros & Cons
* **Advantages:**
  * **Simple & Intuitive:** Easy to understand and configure.
  * **Computational Efficiency:** Prevents deep tree construction, saving memory and training time.
* **Disadvantages:**
  * **Risk of Underfitting:** Stopping too early can produce an overly simple model that misses key data patterns.
  * **Requires Fine-Tuning:** Hyperparameters require careful tuning (e.g., Grid Search).
  * **Short-Sightedness (Greedy Limit):** Can prune a node prematurely that might have led to highly beneficial splits downstream.

---

## 4. Post-Pruning (Backward Pruning)

Post-pruning allows the decision tree to grow to its full depth first, and then recursively prunes unnecessary subtrees based on error-complexity evaluation.

### Key Post-Pruning Strategies
1. **Cost Complexity Pruning (CCP / $\alpha$-Pruning):**
   Introduces a cost parameter $\alpha \ge 0$ that trades off model complexity (number of leaves $\vert{}T\vert{}$) against training error $R(T)$:
   $$R_\alpha(T) = R(T) + \alpha \vert{}T\vert{}$$
   Subtrees with lower overall gain per node are collapsed into single leaf nodes assigned the majority class.
2. **Reduced Error Pruning:**
   Traverses fully grown nodes bottom-up, replacing subtrees with single leaf nodes carrying the most common class. If validation accuracy does not drop, the change is kept.

### Pros & Cons
* **Advantages:**
  * **Prevents Short-Sightedness:** Evaluates entire branch paths after full expansion.
  * **Better Generalization:** Generally yields higher test accuracy than pre-pruning by balancing bias and variance.
* **Disadvantages:**
  * **High Computational Cost:** Requires growing full overfitted trees before pruning them back.
  * **Requires Validation Set:** Methods like Reduced Error Pruning reduce data available for training.
  * **Implementation Complexity:** Involves tuning parameters ($\alpha$) across multiple candidate subtrees.

---

## 5. Summary Table

| Feature | Pre-Pruning (Early Stopping) | Post-Pruning (Backward Pruning) |
| :--- | :--- | :--- |
| **Execution Phase** | During tree construction | After full tree construction |
| **Computational Speed** | Fast ($O(\log N)$ path truncated) | Slower (Full expansion required) |
| **Search Perspective** | Local / Greedy | Global (Subtree evaluation) |
| **Primary Risk** | Underfitting | Moderate risk if over-pruned |
| **Parameters** | `max_depth`, `min_samples_split` | Cost Complexity ($\alpha$), Validation Error |

## 6. Python Code (Scikit-Learn)

```python
from sklearn.datasets import load_iris
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier

# 1. Load Data
X, y = load_iris(return_X_y=True, as_frame=True)
X_train, X_test, y_train, y_test = train_test_split(X, y, random_state=42)

# 2. Pre-Pruned Tree
pre_tree = DecisionTreeClassifier(max_depth=3, min_samples_leaf=5, random_state=42)
pre_tree.fit(X_train, y_train)

# 3. Post-Pruning (Cost Complexity Pruning)
full_tree = DecisionTreeClassifier(random_state=42)
path = full_tree.cost_complexity_pruning_path(X_train, y_train)
ccp_alphas = path.ccp_alphas  # Array of candidate alpha values

post_tree = DecisionTreeClassifier(ccp_alpha=ccp_alphas[2], random_state=42)
post_tree.fit(X_train, y_train)

# 4. Extract Normalized Feature Importances
feature_importances = dict(zip(X.columns, post_tree.feature_importances_))
print("Feature Importances:", feature_importances)
