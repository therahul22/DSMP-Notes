# Ensemble Learning, Hyperparameters, ERT

---

## 1. Core Intuition: Bootstrapping & Decorrelation

* **How it works:** Random Forest is based on **bootstrapping**. We generate multiple random subsets from our main dataset (with replacement) and feed each subset to a separate base model of the same type—specifically, **Decision Trees**.
* **Why Decorrelation is Essential:** The overall success of a Random Forest depends heavily on **how uncorrelated (decorrelated) the individual Decision Trees are**.
  * If all trees make mistakes on the exact same data points (high correlation), ensembling provides no benefit.
  * When trees are decorrelated, their individual errors cancel each other out during aggregation (majority voting or averaging), yielding significantly better performance.

---

## 2. Mathematical Intuition: Why Ensembling Works

To see why decorrelation matters, consider $M$ independent models:
* If models $M_1, M_2, M_3$ are **independent** and trained on different data subsets, there are $2^3 = 8$ possible outcome combinations for any single prediction (ranging from all 3 being wrong to all 3 being correct).
* Since predictions are decided by **majority voting**, the ensemble only fails if the majority (2 or more trees) make a mistake at the same time.
* As long as base models perform better than random guessing ($>50\%$ accuracy) and their errors are uncorrelated, the ensemble error probability drops drastically as the number of trees grows.

> **Clarification / Correction on Decision Trees vs. Random Forest:**
> * **Note Correction:** Random Forest *does* calculate **Feature Importance** (by averaging the impurity reduction/Gini decrease across all trees). 
> * **Why use a single Decision Tree then?** We use a single Decision Tree primarily for **interpretability and inference logic**. A single tree gives explicit, easy-to-read `if-else` rules. A Random Forest acts as a black box where tracing individual decision paths is nearly impossible.

### A. Forest-Level Hyperparameters
1. `n_estimators`: The total number of decision trees built in the forest. 
   * **Note:** To choose the optimal value, plot a graph of **Test Accuracy/Error vs. `n_estimators`**. Select the point where the test error curve plateaus and stabilizes.
2. `max_samples`: Determines the number (or fraction) of rows drawn from the original dataset to train each base tree when bootstrapping.
3. `bootstrap`: Accepts `True` or `False`. Controls whether row sampling is done with replacement (`True`) or without replacement (`False`).
4. `bootstrap_features` / `max_features`: Controls column sampling. By default, Random Forest selects $\sqrt{p}$ features (where $p$ is total features) randomly at each node split to ensure decorrelation.

---

### B. Tree-Level Hyperparameters

> **Interview Question from Notes:** *Random Forest reduces variance, and Pruning also reduces variance—why do we use both?*  
> **Answer:** While Random Forest reduces variance by averaging uncorrelated trees, if individual trees are grown infinitely deep on highly noisy data, the ensemble variance can still remain higher than desired. Applying **tree-level pruning** keeps individual trees constrained, reduces overall training time, and prevents individual trees from overfitting to extreme noise.

#### **Split Criterion**
* `criterion`: Defines the mathematical metric used to measure split quality. Common options include `gini`, `entropy`, or `log_loss` for classification, and `squared_error` or `absolute_error` for regression.

#### **Pre-Pruning Hyperparameters (Constrain tree growth during building)**
* `max_depth`: Limits how deep each decision tree can grow.
* `min_samples_split`: The minimum number of samples required at an internal node to perform a split.
* `min_samples_leaf`: The minimum number of samples that must remain in a leaf node.
* `min_weight_fraction_leaf`: The minimum weighted fraction of the total sum of weights required to be at a leaf node (useful when sample weights are provided).
* `max_leaf_nodes`: Limits the total number of terminal/leaf nodes a tree can have.
* `min_impurity_decrease`: A node will split only if the split induces an impurity decrease greater than or equal to this value.

#### **Post-Pruning Hyperparameters (Trim branches after tree is fully grown)**
* `ccp_alpha` *(Cost-Complexity Pruning Alpha)*: Parameter used to control post-pruning. Higher values of $ lpha$ prune more nodes, turning complex trees into simpler ones.

---

### C. Miscellaneous Hyperparameters
1. `oob_score`: (`True`/`False`) Toggles whether to compute the Out-Of-Bag evaluation score during training.
2. `n_jobs`: Controls parallel processing. Setting `n_jobs=-1` uses all available CPU cores to train trees simultaneously.
3. `random_state`: Controls randomness (e.g., set to `42`) to make model results reproducible across multiple executions.
4. `verbose`: Controls the print output verbosity during training/fitting.
5. `warm_start`: When set to `True`, allows you to reuse a previously fit forest and add more trees (`n_estimators`) without retraining the existing ones from scratch. Useful when dataset sizes or training times are very high.
6. `class_weight`: Handles **imbalanced datasets** by assigning higher loss weights to minority classes (e.g., `class_weight="balanced"`).

## 4. Out-Of-Bag (OOB) Score

* **The Concept:** When sampling $N$ rows with replacement (bootstrapping), mathematically **~36.7% (or 36.8%) of the original dataset rows are left out** for any given tree.
* **How it works:** 
  1. These leftover points are called **Out-of-Bag (OOB)** samples for that specific tree.
  2. Because these rows were never seen during that tree's training, they serve as a built-in validation set.
  3. We pass each row through only those trees that *did not* use it during training and aggregate their predictions.
* **Why it's useful:** It eliminates the need for a separate validation split, preserving training data—especially critical when working with smaller datasets.

---

## 5. Extremely Randomized Trees (Extra Trees)

* **Goal:** Introduce an extra layer of randomness to decorrelate decision trees even further.
* **Difference from Random Forest:**
  * **Random Forest:** Evaluates feature splits and mathematically calculates the *optimal split threshold* (e.g., Gini/Entropy minimization).
  * **Extra Trees:** Picks a **completely random split threshold** for each feature candidate.
* **Impact:**
  * **Training Accuracy:** Slightly decreases on training data because splits are arbitrary.
  * **Speed & Variance:** Significantly speeds up training time (no optimal split math required per node) and further reduces overall ensemble variance.

---

## 6. Summary: Advantages & Disadvantages

| Advantages | Disadvantages |
| :--- | :--- |
| Efficiently handles high-dimensional and large datasets. | **Black Box Model:** Lacks the clear, step-by-step interpretability of single decision trees. |
| Reduces overall variance without significantly increasing bias. | Higher memory usage and inference execution time due to storing multiple trees. |
| Built-in validation capability via **OOB Score**. | Can struggle on extremely sparse high-dimensional data (e.g., text vectorization). |
