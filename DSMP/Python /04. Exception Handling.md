## 1. Exception Handling Mechanics 💡 *(Interview Topic)*

### Errors vs. Exceptions
* **Syntax Errors:** Identified during the parsing/compilation stage before execution. The program fails to start (e.g., missing colons, unbalanced parentheses).
* **Exceptions:** Logical/runtime errors occurring during execution while syntactically correct code is running (e.g., `ZeroDivisionError`, `FileNotFoundError`).

> **Note:** In Python, all standard exceptions derive from the base `BaseException` or `Exception` classes.

### Why Exception Handling is Essential
1. **User Experience (UX):** Prevents abrupt application crashes, providing clean, user-friendly feedback instead of raw stack traces.
2. **Security:** Raw stack traces can leak internal server paths, database variable names, and architectural details to external users.

### Python vs. Java Exception Keyword Mapping
| Concept | Python Keyword | Java Equivalent |
| :--- | :--- | :--- |
| **Guarded Execution** | `try` | `try` |
| **Catching Errors** | `except` | `catch` |
| **Raising Exceptions** | `raise` | `throw` |
| **Success Callback** | `else` | *(N/A)* |
| **Cleanup Execution** | `finally` | `finally` |

### Complete `try-except-else-finally` Block Structure
```python
try:
    num1 = int(input("Enter numerator: "))
    num2 = int(input("Enter denominator: "))
    result = num1 / num2
except ZeroDivisionError as e:
    print(f"Error: Cannot divide by zero! ({e})")
except ValueError as e:
    print(f"Error: Invalid input type! ({e})")
except Exception as e:
    print(f"Generic Error Caught: {e}")
else:
    # Runs ONLY if NO exception was raised in the try block
    print(f"Division Successful! Result = {result}")
finally:
    # ALWAYS executes regardless of whether an exception occurred or was handled
    print("Execution complete. Cleaning up resources/closing file handles...")
```

### Raising Custom Exceptions
Custom exceptions give developers control over application-specific domain logic (e.g., preventing negative account balances). Custom exception classes **must inherit** from the built-in `Exception` class.

```python
class InvalidAgeException(Exception):
    """Custom exception raised when an age does not meet criteria."""
    def __init__(self, message="Age must be 18 or above."):
        self.message = message
        super().__init__(self.message)

def verify_voter(age):
    if age < 18:
        raise InvalidAgeException(f"Access Denied: Provided age is {age}")
    print("Voter Verified Successfully!")

try:
    verify_voter(16)
except InvalidAgeException as e:
    print(e)  # Output: Access Denied: Provided age is 16
```

## 2. Namespaces & Scope Resolution (The LEGB Rule) 💡 *(Interview Topic)*

A **Namespace** in Python is internally represented as a **dictionary** mapping identifiers (variable names) as keys to their corresponding objects in memory as values (`key: Identifier, value: Object`).

```python
# View local and global namespaces
print(locals())  # Dictionary of current local symbols
print(globals()) # Dictionary of module global symbols
```

### Scope Resolution Order: **LEGB Rule**
When looking up a variable, Python searches through nested namespaces in a strict order:

$$\text{Local (L)} \longrightarrow \text{Enclosing (E)} \longrightarrow \text{Global (G)} \longrightarrow \text{Built-in (B)}$$

1. **Local (L):** Variables defined inside the currently executing function or lambda.
2. **Enclosing (E / Non-Local):** Variables defined inside the outer wrapping functions of nested functions.
3. **Global (G):** Variables defined at the top level of the module/script.
4. **Built-in (B):** Pre-loaded Python names (`len`, `print`, `enumerate`, `eval`, `dir`).

```python
# Modifying variable scopes using keywords
x = "Global"

def outer():
    x = "Enclosing"
    def inner():
        nonlocal x  # Target the enclosing scope variable
        x = "Modified Enclosing"
        
        global y    # Create/Modify a variable in the global namespace
        y = "Newly Global"
    inner()
    print("Outer x:", x)

outer()  # Output: Outer x: Modified Enclosing
print("Global y:", y)  # Output: Global y: Newly Global
```

> **Warning regarding Built-ins:** Standard built-in names can be overridden in the local or global namespace (e.g., `print = 10`), which shadows the built-in function until deleted using `del print`.

## 3. Iterators vs. Iterables vs. Generators

### Core Concepts
* **Iterable:** Any Python object capable of returning its elements one at a time (e.g., `list`, `str`, `tuple`). An iterable implements the `__iter__()` method.
* **Iterator:** An object that statefully tracks its traversal across a sequence **without holding the entire dataset in memory simultaneously**. It implements the Iterator Protocol:
  * `__iter__()`: Returns the iterator object itself.
  * `__next__()`: Fetches the next element or raises `StopIteration` when depleted.

```python
# Creating an iterator manually from an iterable
my_list = [10, 20]
my_iter = iter(my_list)  # Calls my_list.__iter__()

print(next(my_iter))  # Output: 10
print(next(my_iter))  # Output: 20
# next(my_iter)       # Raises StopIteration Exception
```

### Custom Iterator Implementation
```python
class CountDown:
    def __init__(self, start):
        self.current = start

    def __iter__(self):
        return self

    def __next__(self):
        if self.current <= 0:
            raise StopIteration
        val = self.current
        self.current -= 1
        return val

for num in CountDown(3):
    print(num)  # Outputs: 3, then 2, then 1
```

### Generators & The `yield` Keyword
A **Generator** is an elegant, simplified way to write an iterator using standard function syntax.

* **`return` vs. `yield`:**
  * `return` terminates function execution completely and destroys local variable stack states.
  * `yield` returns a value to the caller, **pauses function execution**, and preserves the local execution state and variable space for the next invocation.

```python
# Generator function example
def fibonacci_generator(limit):
    a, b = 0, 1
    count = 0
    while count < limit:
        yield a
        a, b = b, a + b
        count += 1

# Lazy evaluation: Memory consumption remains O(1) regardless of sequence size
fib = fibonacci_generator(5)
for val in fib:
    print(val)  # Outputs: 0, 1, 1, 2, 3
```

## 4. First-Class Functions, Closures & Decorators

### 1. First-Class Functions
In Python, functions are **First-Class Citizens**, meaning they behave like standard objects. Functions can be:
* Assigned to variables.
* Passed as positional arguments to other functions.
* Returned as values from within other functions.

### 2. The Closure Property 💡 *(Interview Topic)*
A **Closure** is an inner function that retains access to variables from its enclosing lexical scope (outer function), **even after the outer function has finished executing and its stack frame is popped**.

```python
def outer_multiplier(factor):
    # 'factor' is in the enclosing scope
    def inner_calculator(number):
        return number * factor  # Captures 'factor' via closure
    return inner_calculator

double = outer_multiplier(2)  # outer_multiplier has finished execution
triple = outer_multiplier(3)

print(double(10))  # Output: 20
print(triple(10))  # Output: 30
```

### 3. Decorators
A **Decorator** is a function that takes another function as an argument, dynamically adds behavior/functionality ("decorates" it), and returns the modified function wrapper—all without altering the original function's source code.

#### Syntax Abstraction
```python
@my_decorator
def my_func():
    pass

# Is syntactically equivalent to:
# my_func = my_decorator(my_func)
```

#### Custom User-Defined Decorator Example (Execution Timer)
```python
import time

def execution_logger(func):
    def wrapper(*args, **kwargs):
        print(f"--- Executing function: {func.__name__} ---")
        start_time = time.time()
        
        result = func(*args, **kwargs)  # Executes actual function
        
        end_time = time.time()
        print(f"Finished {func.__name__} in {end_time - start_time:.4f}s")
        return result
    return wrapper

@execution_logger
def calculate_squares(n):
    return [i**2 for i in range(n)]

calculate_squares(100000)
```

### Built-in Python Decorators Overview
* **`@classmethod`:** Binds a method to the class scope (`cls`) rather than instances.
* **`@staticmethod`:** Defines utility functions inside class namespaces without binding `self` or `cls`.
* **`@property`:** Turns class methods into read-only getter attributes, supporting associated `.setter` and `.deleter` decorators.
* **`@abstractmethod`:** Enforces implementation of base class signatures inside derived subclasses.
