## 1. Core Mechanics: Classes, Objects & Memory

In Python, **everything is an object** (including integers, functions, and modules). OOP allows developers to create custom user-defined data types by combining data (attributes) and behavior (methods) into a single blueprint.

```python
# Creating an instance (Object) of a custom or built-in class
list1 = list()       # Standard list object creation
string1 = str()      # Standard string object creation
```

### Class vs. Object Blueprint
* **Class:** A user-defined template/blueprint defining the data attributes and methods available to its instances.
* **Object:** An actual instance of the class instantiated in memory.

### Object Instantiation & Memory Reference
```python
class Human:
    pass

model = Human()  # Instantiates an object of class Human
```
Here, `Human` refers to the class definition, whereas `Human()` creates a new object in heap memory. The variable `model` stores the **memory reference address** pointing to that object.

## 2. Special Methods (Magic Methods) & Self Mechanics

### 1. The Constructor (`__init__`)
The `__init__` method is a special magic (dunder) method that executes **automatically** upon object instantiation.

```python
class DatabaseConnection:
    def __init__(self, db_url):
        # Configuration code executed automatically
        self.db_url = db_url
        print(f"Connected to: {self.db_url}")

# Instantiation automatically triggers __init__
conn = DatabaseConnection("localhost:5432")
```

> 💡 **Interview Prep Note:** Constructors are primarily used to set up object state or execute configuration logic (e.g., establishing database connections, opening file streams) that shouldn't depend on manual caller invocation.

### 2. The `self` Parameter
Methods inside a class are functions bound to that class. By default, methods **cannot** directly access other methods or instance attributes unless called via `self`.

* **`self`** represents the **instance calling the method**.
* Python automatically passes the calling object reference as the first argument when calling a method (e.g., `obj.method()` translates internally to `Class.method(obj)`).

```python
class Calculator:
    def add(self, a, b):
        return a + b

    def Display_sum(self, a, b):
        # Accessing another method within the class using self
        result = self.add(a, b)
        print(f"Sum is: {result}")
```

### 3. String Representation (`__str__`)
When an object is passed to `print()` or `str()`, Python invokes its `__str__` method to retrieve a human-readable string representation of the object.

```python
class User:
    def __init__(self, name, role):
        self.name = name
        self.role = role

    def __str__(self):
        return f"User(Name: {self.name}, Role: {self.role})"

user1 = User("Rahul", "Developer")
print(user1)  # Output: User(Name: Rahul, Role: Developer)
```

### 4. Destructors (`__del__`)
The destructor method `__del__` is called automatically when an object's reference count drops to zero or when it is explicitly deleted using `del`, freeing up memory allocations.

```python
class Resource:
    def __del__(self):
        print("Resource cleaned up from memory.")

res = Resource()
del res  # Output: Resource cleaned up from memory.
```

## 3. Pass by Reference & Object Mutability 💡 *(Interview Topic)*

When an object is passed to a function outside of a class, it is passed by **reference** (the function receives a copy of the object's memory address reference).

* Objects like lists, dicts, and custom class instances are **mutable** by default—modifying them inside a function directly mutates the original object outside the function.

```python
class Customer:
    def __init__(self, name):
        self.name = name

def update_name(customer_obj, new_name):
    customer_obj.name = new_name  # Mutates original object in memory

c = Customer("Amit")
update_name(c, "Rahul")
print(c.name)  # Output: Rahul
```

## 4. Encapsulation, Name Mangling & Variable Scopes

**Encapsulation** is the bundling of data and the methods that operate on that data into a single unit, while restricting direct outside access to critical internal states.

### Instance Variables vs. Static (Class) Variables
* **Instance Variables:** Variables specific to each individual object. Defined using `self.variable_name`.
* **Static / Class Variables:** Variables shared across **all instances** of a class. Defined directly within the class body and accessed using `ClassName.variable_name`.

```python
class Student:
    school_name = "IIT Delhi"  # Static / Class Variable (Shared)

    def __init__(self, name):
        self.name = name       # Instance Variable (Unique per object)
```

### Name Mangling & Private Attributes
In Python, prepending an attribute name with double underscores (`__varName`) marks it as **private**.

However, Python enforces privacy through **Name Mangling**:
* Internally, `__varName` is renamed to `_ClassName__varName`.
* Direct assignment like `obj.__varName = "value"` merely creates a *new* public attribute on the fly rather than modifying the private attribute.

```python
class Account:
    def __init__(self, balance):
        self.__balance = balance  # Private attribute

acc = Account(1000)

# Attempting direct access raises AttributeError
# print(acc.__balance) 

# Name Mangling Bypass (Proves nothing is strictly private in Python):
print(acc._Account__balance)  # Output: 1000
acc._Account__balance = 2000  # Modifies private variable
```

> ❓ **Interview Question: Is true privacy supported in Python?**
>
> **Answer:** No. Python operates on the philosophy of *"we are all consenting adults here"*. Private attributes are mangled to `_ClassName__attribute` to prevent accidental overrides, but they remain accessible if accessed explicitly by their mangled names.

### Getters and Setters
To prevent accidental data corruption or invalid inputs, access private variables via public **Getters** and **Setters**, where input verification logic can be enforced.

```python
class BankAccount:
    def __init__(self, balance):
        self.__balance = balance

    def get_balance(self):  # Getter
        return self.__balance

    def set_balance(self, amount):  # Setter
        if amount >= 0:
            self.__balance = amount
        else:
            raise ValueError("Balance cannot be negative")
```

### Static Methods (`@staticmethod`)
Static methods do not take `self` or `cls` as their first argument. They behave like utility functions housed inside a class namespace.

```python
class MathUtility:
    @staticmethod
    def is_even(num):
        return num % 2 == 0

print(MathUtility.is_even(10))  # Output: True
```

## 5. Relationships: Aggregation vs. Inheritance

### Aggregation ("Has-A" Relationship)
Aggregation represents a relationship where one class owns or holds an object of another class as an attribute. The owner class **cannot** directly access private attributes of the aggregated class without getters/setters.

```python
class Address:
    def __init__(self, city, state):
        self.city = city
        self.state = state

class Person:
    def __init__(self, name, address_obj):
        self.name = name
        self.address = address_obj  # Has-A Relationship

add = Address("New Delhi", "Delhi")
p = Person("Rahul", add)
print(p.address.city)  # Output: New Delhi
```

## 6. Inheritance ("Is-A" Relationship)

Inheritance enables a child class to inherit features (constructors, non-private methods, non-private attributes) from a parent class for code reusability.

```python
# Base Syntax
class ChildClass(ParentClass1, ParentClass2):
    pass
```

### What gets inherited?
* ✅ Constructors (`__init__`)
* ✅ Non-Private Attributes
* ✅ Non-Private Methods
* ❌ Private Attributes (`__varName`) are **not** directly inherited (must be accessed via parent Getter methods).

### Method Overriding & The `super()` Function
Child classes can override methods inherited from parent classes. The `super()` function allows access to parent class methods directly within the child class context.

> **Constraint:** `super()` can **only** be used to invoke parent *methods*, not to directly access parent *attributes*.

```python
class Parent:
    def __init__(self, name):
        self.name = name

    def show(self):
        print("Parent method execution")

class Child(Parent):
    def __init__(self, name, age):
        super().__init__(name)  # Calling parent constructor
        self.age = age

    def show(self):
        super().show()          # Invoking parent method
        print("Child overridden method execution")

c = Child("Rohan", 20)
c.show()
```

### Types of Inheritance
1. **Single Inheritance:** `A -> B`
2. **Multilevel Inheritance:** `A -> B -> C`
3. **Hierarchical Inheritance:** `A -> B` and `A -> C`
4. **Multiple Inheritance:** `A, B -> C` *(Prone to the Diamond Problem)*
5. **Hybrid Inheritance:** Combination of two or more inheritance patterns.

```python
# Multiple Inheritance & Method Resolution Order (MRO)
class A:
    def greet(self):
        print("Hello from A")

class B:
    def greet(self):
        print("Hello from B")

class C(A, B):  # Order determines lookup precedence
    pass

obj = C()
obj.greet()  # Output: "Hello from A" (Follows C.mro())
```

## 7. Polymorphism

Polymorphism allows objects of different classes to respond to identical method names in class-specific ways.

### 1. Method Overriding
Occurs when a child class redefines a method that already exists in its parent class.

### 2. Method Overloading (Simulated in Python)
Python does not natively support traditional compile-time function overloading (having multiple functions in the same scope with identical names but different parameter signatures). Writing multiple methods with the same name will cause the last defined method to overwrite previous ones.

*Workaround:* Default parameters or variable arguments (`*args`, `**kwargs`).
```python
class MathOp:
    def add(self, a, b, c=0):  # Handles both 2-arg and 3-arg additions
        return a + b + c
```

### 3. Operator Overloading
Allows standard built-in operators (`+`, `-`, `*`, `==`, etc.) to operate on custom user-defined objects by overriding magic methods (e.g., `__add__`, `__sub__`, `__eq__`).

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    # Overloading the '+' operator
    def __add__(self, other):
        return Point(self.x + other.x, self.y + other.y)

    def __str__(self):
        return f"({self.x}, {self.y})"

p1 = Point(1, 2)
p2 = Point(3, 4)
print(p1 + p2)  # Output: (4, 6)
```

## 8. Abstraction & Abstract Base Classes (ABC)

**Abstraction** hides internal implementation complexities while enforcing architectural contracts on subclass implementations.

### Rules of Abstract Base Classes:
1. Abstract classes **cannot** be directly instantiated.
2. An abstract class contains at least one **abstract method** (a method decorated with `@abstractmethod` containing no body implementation).
3. Derived subclasses **must** override and implement all abstract methods to be instantiated.

```python
from abc import ABC, abstractmethod

class PaymentGateway(ABC):  # Inherits from ABC
    @abstractmethod
    def process_payment(self, amount):
        """Abstract method - enforcing implementation in subclasses"""
        pass

class UPIPayment(PaymentGateway):
    def process_payment(self, amount):
        print(f"Processing UPI payment of INR {amount}")

# gateway = PaymentGateway()  # Raises TypeError: Cannot instantiate abstract class
pay = UPIPayment()
pay.process_payment(500)     # Output: Processing UPI payment of INR 500
```
