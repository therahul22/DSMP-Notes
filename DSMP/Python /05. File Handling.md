# Lecture 4 (Part 2): Python File Handling — I/O Operations, Serialization & Pickling


## 1. The File I/O Story: How Operating Systems Handle Files

Every program operates in volatile Memory (RAM). When execution terminates, volatile memory clears. To retain data permanently, applications interact with non-volatile Storage (Hard Drives/SSDs) via **File I/O**.

```
┌─────────────────┐       open()       ┌─────────────────┐       Read/Write      ┌─────────────────┐
│ Python Program  │ ─────────────────> │ Operating System│ ────────────────────> │ Disk Storage    │
│  (RAM Memory)   │ <───────────────── │  (Buffer Stream)│ <──────────────────── │   (Text/Binary) │
└─────────────────┘      close()       └─────────────────┘                       └─────────────────┘
```

### The Standard 3-Step I/O Lifecycle
1. **Open the File:** Request the Operating System (OS) to locate the file on disk and create a stream buffer between RAM and storage. Returns a **File Handle/Stream Pointer**.
2. **Read/Write Data:** Perform operations sequentially using the stream pointer.
3. **Close the File:** Flush residual buffered data to disk and free system resources back to the OS.

---

## 2. Opening & Writing to Text Files (`open()`)

The `open(file, mode)` function establishes a handle between Python and the target file.

```python
# Syntax: open(filename, mode, encoding)
f = open("sample.txt", "w")
f.write("Hello World!")
f.close()
```

### File Modes Breakdown

| Mode | Name | Behavior | Creates File if Missing? | Truncates (Erases) File? |
| :--- | :--- | :--- | :--- | :--- |
| **`'w'`** | Write | Overwrites file from start. | **Yes** | **Yes** |
| **`'a'`** | Append | Appends data to end of file. | **Yes** | **No** |
| **`'r'`** | Read | Opens file for reading (Default). | **No** *(Raises FileNotFoundError)* | **No** |
| **`'b'`** | Binary | Appends binary mode flag (e.g., `'rb'`, `'wb'`). | Depends on primary mode | Depends on primary mode |

### The Problem with `'w'` Mode & The Append (`'a'`) Solution
Using `'w'` mode erases existing contents entirely upon execution. To preserve existing data while adding new entries, use Append Mode (`'a'`).

```python
# Append Mode ('a') preserves existing content
f = open("sample.txt", "a")
f.write("\nAppended line without overwriting existing data.")
f.close()

# Writing multiple lines at once using .writelines()
lines = ["Line 1\n", "Line 2\n", "Line 3\n"]
f = open("sample.txt", "a")
f.writelines(lines)
f.close()
```

### Absolute vs. Relative File Paths
Files can be saved anywhere on the host filesystem by providing full paths:

```python
# Relative Path (Saves in current working directory)
f1 = open("data.txt", "w")

# Absolute Path (Windows / Linux syntax)
f2 = open("C:/Users/Rahul/Documents/notes.txt", "w")
```

## 3. Reading Files (`read()`, `readline()`, Chunks)

### 1. Simple Reading (`read()`, `readline()`, `readlines()`)
```python
f = open("sample.txt", "r")

# Read entire file as single continuous string
content = f.read()

# Read single line up to '\n'
f.seek(0)
first_line = f.readline()

# Read all lines into a Python list of strings
f.seek(0)
all_lines = f.readlines()

f.close()
```

### 2. Reading Large Files Efficiently (Buffer & Chunk Management) 💡 *(Interview Topic)*
> **Problem:** Loading a 10GB dataset using `.read()` will crash system memory (RAM Overflow).
>
> **Solution:** Use **Iterators** or fixed-size **Chunk Streams** to process data lazily.

```python
# Method A: Line-by-Line Iteration (Low memory overhead, highly efficient)
with open("big_data.txt", "r") as f:
    for line in f:
        print(line.strip())

# Method B: Fixed-Character Chunking (Useful for unformatted large files)
with open("big_data.txt", "r") as f:
    chunk_size = 10  # Process 10 characters at a time
    while True:
        chunk = f.read(chunk_size)
        if not chunk:
            break  # End of file (EOF) reached
        print(chunk, end='|')
```

## 4. Resource Management: Context Managers (`with` Statement)

Failing to explicitly call `.close()` can lead to **memory leaks** and **file locks**. The `with` statement leverages Python's Context Manager protocol (`__enter__` and `__exit__`), ensuring file handles close automatically—even if runtime exceptions occur.

```python
# Recommended Industry Standard Practice
with open("sample.txt", "r") as f:
    data = f.read()
    # Perform operations...

# File handle is automatically closed here outside the context block
print(f.closed)  # Output: True
```

## 5. Controlling File Pointers: `tell()` and `seek()`

* **`tell()`:** Returns the current position of the file pointer (in bytes).
* **`seek(offset)`:** Moves the file pointer to a specific byte location.

```python
with open("sample.txt", "w+") as f:
    f.write("Hello Python")
    
    print("Pointer Position:", f.tell())  # Output: 12 (at end of text)
    
    # Move pointer back to beginning of file
    f.seek(0)
    print("After seek(0):", f.tell())    # Output: 0
    print("Read content:", f.read())      # Reads from start again
```

## 6. Binary Files vs. Text Files

* **Text Files (`.txt`):** Encoded as character sequences (e.g., UTF-8, ASCII). The OS translates raw bytes into readable characters.
* **Binary Files (`.jpg`, `.mp3`, `.pdf`, `.exe`):** Raw byte streams representing non-textual data structure.

```python
# Image Copy Routine (Reading & Writing Raw Bytes)
with open("source.jpg", "rb") as source_file:
    with open("destination_copy.jpg", "wb") as target_file:
        chunk_size = 4096  # 4KB Buffer
        while True:
            buffer = source_file.read(chunk_size)
            if not buffer:
                break
            target_file.write(buffer)
```

## 7. Serialization & Deserialization (JSON & Pickle) 💡 *(Interview Topic)*

### Core Concepts
* **Serialization:** The process of converting complex in-memory Python objects (dicts, tuples, custom classes) into a flattened format (JSON string or Byte Stream) suitable for storage or network transmission.
* **Deserialization:** Reconstructing stored flattened representations back into active Python memory structures.

```
┌─────────────────────────────────┐                       ┌─────────────────────────────────┐
│ Python Object                   │   Serialization       │ Data Stream                     │
│ (Dict, List, Custom Class)      │ ────────────────────> │ (JSON Text or Binary Bytes)     │
│                                 │ <──────────────────── │                                 │
└─────────────────────────────────┘   Deserialization     └─────────────────────────────────┘
```

---

### 1. Structured Text Serialization: `json` Module

JSON (JavaScript Object Notation) is a human-readable standard format for structured data exchange across programming languages.

#### Primary JSON Methods
* **`json.dump(obj, file)`:** Serializes Python object directly to an open **file stream**.
* **`json.dumps(obj)`:** Serializes Python object to a **JSON string**.
* **`json.load(file)`:** Deserializes JSON data from an open **file stream** into Python objects.
* **`json.loads(string)`:** Deserializes a **JSON string** into Python objects.

```python
import json

# Data Structure (Dict, List, Tuple)
user_profile = {
    "name": "Rahul",
    "roles": ["Admin", "Developer"],
    "details": {"id": 101, "active": True},
    "coordinates": (12.97, 77.59)  # Note: JSON converts tuples to arrays []
}

# 1. Serialization to File (dump)
with open("profile.json", "w") as f:
    json.dump(user_profile, f, indent=4)

# 2. Deserialization from File (load)
with open("profile.json", "r") as f:
    loaded_profile = json.load(f)

print(type(loaded_profile))  # Output: <class 'dict'>
```

#### Serializing Custom Objects with Custom Encoders
Standard JSON serializers cannot handle custom class instances out of the box (raises `TypeError`). You must provide a custom encoder function or inherit from `json.JSONEncoder`.

```python
import json

class Student:
    def __init__(self, name, marks):
        self.name = name
        self.marks = marks

# Custom conversion function
def custom_encoder(obj):
    if isinstance(obj, Student):
        return {"__class__": "Student", "name": obj.name, "marks": obj.marks}
    raise TypeError("Object of type Student is not JSON serializable")

student_obj = Student("Rahul", 95)

# Serialize custom object
json_str = json.dumps(student_obj, default=custom_encoder)
print(json_str)  # Output: {"__class__": "Student", "name": "Rahul", "marks": 95}
```

### 2. Binary Object Persistence: `pickle` Module

`pickle` is Python's native binary serialization framework capable of serializing almost **any Python object** (including custom class instances and functions) into a binary stream.

```python
import pickle

class Person:
    def __init__(self, name, age):
        self.name = name
        self.age = age

p1 = Person("Alice", 25)

# Pickling (Serialization to binary file using 'wb')
with open("person.pkl", "wb") as f:
    pickle.dump(p1, f)

# Unpickling (Deserialization from binary file using 'rb')
with open("person.pkl", "rb") as f:
    restored_person = pickle.load(f)

print(restored_person.name)  # Output: Alice
```

## 8. `pickle` vs `json` Comparison 💡 *(Interview Topic)*

| Feature | `json` | `pickle` |
| :--- | :--- | :--- |
| **Data Format** | Human-readable Text (UTF-8) | Binary Byte Stream |
| **Language Compatibility** | Interoperable across all languages (Language Agnostic) | **Python Specific** (Cannot be parsed in Java/C++) |
| **Security Risk** | Safe (Only parses structured data primitives) | **Unsafe** (Deserializing untrusted pickle streams can execute arbitrary system code!) |
| **Custom Object Support** | Requires custom encoder/decoder functions | Handles complex custom classes natively out-of-the-box |
| **Performance** | Slower for complex nested native objects | Optimized and faster for complex Python object graphs |
